## 远端建议与本地开发

每个新开发任务可采用以下流程，同一任务内的修复和界面迭代不必重新咨询。远端咨询是辅助决策；用户直接派发的明确小修改可以由本地主代理按同样边界直接处理。

1. **本地主代理准备一份纲要。** 写用户动作、纳入/暂缓范围、必要约束、几个待调查问题和停止点。初始不必有逐文件步骤、固定测试数量或完整接口设计。附仓库 URL、建议调查的 ref，以及本地 HEAD/相关未提交差异的摘要；本地 HEAD 不能冒充远端可访问提交。
2. **用户转交给远端只读 agent。** 远端尽量解析并记录实际读取的完整 commit SHA、日期和附件清单；确实无法获取时明说未知，由本地核对相关事实，不能用事后查询倒填；按相关性读代码/契约，区分事实、建议和未验证项。附件中的新范围优先于旧派发顺序，但不得当作已合入代码。无法访问的文件直接列明，不推测其内容。
3. **用户带回行动建议。** 建议保存为 `RF-01-advice.md`（后续任务类推）放在本目录；附件可放同名前缀的子目录。本地 agent 可代为保存用户提供的内容。保留远端原文及基线，不默默修改它来配合实施；不创建虚假的“已收到”占位报告。
4. **本地主代理核对后开工。** 比较建议的 SHA、本地 HEAD、相关已提交/未提交改动与当前入口，只复核受影响边界。在 `docs/work-guidance/<任务ID>.md` 补短小的“本地执行记录”：采纳/调整/暂缓建议、允许修改范围、必要契约对齐、验证命令与停止点。可行的普通实现取舍由本地负责，不因无关提交变化退回调查。影响结论的变化才做针对性补查；缺少必要产品决定仅暂停相关分支。
5. **交付同一用户动作。** 在同一份本地指导中补结果、实际命令、视觉证据和已知缺口。涉及契约的工作做一次变更协调检查；普通样式调整用视觉及针对性静态检查。没有阻塞发现便交付，不为清零非阻塞建议追加全仓工作。

远端无法读取本地未提交文件。若纲要/新决策尚未发布，直接把文件作为咨询附件，至少附足以解释与远端旧规则差异的内容；远端仍缺必要资料时列明。提交和推送由单独授权决定，本流程不自动发布本地改动，也不要求为了咨询提交整个工作树。

远端建议不是验收报告。远端在隔离环境跑过的测试须标明环境与提交，本地仍需验证实际改动；没有运行就写“建议命令”。建议过时不意味着全部作废，保留仍成立的部分。

项目提供只读角色 [`learningj_reconciler`](../../.codex/agents/learningj_reconciler.toml)，模型为 `gpt-5.6-luna`。在契约影响任务的开工与交付时由主代理按需调用；这是调用约定，不是文件监控或定时自动化。角色只报告差异及最小修复建议，主代理负责采纳与执行。

配置采用 [OpenAI 官方项目级子代理格式](https://learn.chatgpt.com/docs/agent-configuration/subagents)。若当前会话未加载该角色，用通用原生子代理读取该文件的 `developer_instructions` 执行，保持只读职责；不要求用户为一次检查重启工具。不声称本轮已验证新会话的角色自动发现。
