## 原则

围绕可完成的用户操作派发纵向任务。每次只详细定义最近一个可实施任务，后续保持粗粒度；不预先编写整套新契约依赖网。

已投入的工作通过复用可验证能力回收，不通过继续完成无关阶段回收。旧报告保存为历史证据；能力是否可复用需看当前入口和相关测试，不依赖 `STATUS: done`。

| Study/Knowledge/Review 页面与未来 fixture repositories | 冻结功能开发，计划从日常阅读路径隔离 | 阅读器打开不依赖未来 fixture；是否移入演示入口在具体任务中决定 |
| evidence、统计、学习索引 | 暂不扩展；检查实际读写依赖再决定断开 | 不把仍被 reader/token/API 使用的模块当死代码删除 |
| 旧测试与报告 | 保存证据，测试按新标准分类 | 不以删除测试隐瞒回归，也不锁死历史数量和旧目录 |

冻结指不新增功能、不让新阅读器依赖它；不是立即删除代码、数据表或历史文件。替换完成后，确认无运行引用、无用户数据责任，再单独删除旧路径；以 git 历史保留代码，不额外复制一个永久 legacy 应用。

派发前查看实际工作树并记录本动作涉及的已有修改，不能把规划时的清单当持续状态源。已有未提交文件和未跟踪 demo/、experiments/ 等材料不因切换而成为清理对象；先识别归属，不回滚、不覆盖、不代为提交。

## 前端按功能归属渐进组织

建议目标结构：

```text
src/
  app/                 路由、应用装配、全局 provider
  shells/              布局壳
  screens/             薄页面装配，可逐步收敛
  features/
    library/           素材库与导入
    reader/            正文、目录、位置、显示设置
    dictionary/        词典管理与查词
    annotations/       选区操作、批注列表与编辑
  components/ui/       共享 UI 原语
  lib/                 真正共享的文本/API 基础工具与生成类型
```

不先建所有空目录；哪个功能正在实现，就搬迁其内聚组件、hooks、数据访问和测试。每个功能不强制再拆 api/model/ui 三层。跨功能只暴露少量明确接口，避免 reader 与 dictionary 相互导入内部状态。

迁移不能绕过现有 `components/**` 的 shell/router lint 约束：功能内的可复用视图仍保持 props/callback 边界，迁移时把等价静态规则覆盖到新目录，页面装配与 hooks 职责明确。不以新增 feature 目录为由将整个阅读状态搬入组件。

后端保留现有领域分包，优先在被修改时拆分集中的 API 注册与 EPUB 处理逻辑；不引入微服务、通用插件框架或一整套仓储抽象作为前置工作。

## 一个任务的派遣模板

> 用户操作：完成什么可操作闭环。
> 范围：本次纳入与暂缓事项。
> 当前证据：相关真实入口、缺口、依赖及工作树归属。
> 允许修改：完整动作所需的前后端和测试范围；若需契约对齐，另列主代理可修改的文件/章节，先记录决定再实施。
> 验收：一条真实流程 + 必要错误/恢复路径，按 testing-standard 选择命令。
> 收场：旧入口如何切换、遗留依赖怎样记录；不偷偷保留双写。
> 停止：达到用户动作验收即交付，不扩展到下一阶段。

高风险定位/数据写入变化适合独立只读评审；日常样式迭代以视觉确认与针对性检查交付。需要评审时直接记录可操作发现，不让非阻塞建议自动衍生新一轮全量验收。

阅读、查词和批注在目标书上可靠后，重新评估最小 AI 解析闭环；通用 EPUB 兼容、分页与排版完善不是其无限前置条件。当前不提前编写下一批完整任务包。
