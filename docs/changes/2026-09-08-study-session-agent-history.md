## 2. 学习会话迁移

当前权威：[data-model §4](../data-model.md#4-学习会话工作文档与提取)、[ADR-037](../adr/037-study-session.md)。

| 旧假设 | 新契约／后续任务影响 |
|---|---|
| 收件箱查询 Analysis 或 default KP 即可表达学习流程 | StudySession 是活动单位；学习队列、学习记录、知识库分别查询 |
| 等生成完成才能打开有效学习页 | 创建会话后即能打开，准备阶段显示原句与运行状态 |
| 多选必然 batch、不能追问 | 普通多选创建多个 interactive 单句会话；automatic 明确选择 |
| batch/background 默认抽取后可以自动建卡 | automatic 只跳过讨论；所有新卡都须用户 srs 决定，default 初值不授权排程 |
| 导航／关闭事件可以作为后台结束依据 | 导航、关窗不结束讨论、不提取；取消旧 background 自动关闭类型 |
| default KP 清空等于会话完成 | 按本次 run 保存 SessionConfirmation；只能沿用有决定记录的 user 选择，default 必须明确选择 |
| 知识库选择变化影响旧待办 | 完成会话不复活；旧确认保留当时快照 |
| 不想处理的会话无限滞留 | 搁置／恢复与完成、删除分开；在途写入先完成或确认取消 |

更新 API、轮询、缓存失效、路由和组件任务时须使用一份会话状态，不在 Analysis 和前端再复制业务状态机。知识库修改意愿与会话确认复用同一用户决定写入路径。

## 3. Agent 与上下文迁移

当前权威：[prompt-contracts §3](../prompt-contracts.md#3-讨论-agent)、[ADR-038](../adr/038-document-agent.md)。

- 将“一次追问 + 只 add 小节”的交付改为可多轮交流与文档编辑。需要增加替换、删除、移动／合并语义、版本冲突、部分运行失败反馈，不能只把 UI 改名。
- Study 主区文档、右侧对话；窄屏可切换，保留会话、输入草稿和位置。原先折叠消息列表不是完整替代。
- 工具适配须验证原生调用或结构化操作能进入同一执行器；能力不足明确只读降级。不要让每家 provider 形成独立业务写入路径。
- 用户原始消息不含自动拼接文档；每轮组装当前文档、学习上下文和必要历史。摘要保留未进入文档的用户决定；工具调用与结果成对保留／裁切。
- AgentRun、用户可见 AnalysisMessage 与工具协议／副作用记录分开。旧每 turn 仅 user/assistant 各一条的唯一约束不足以表达工具循环。
- 版本检查、(agent_run_id, call_id) 与输入 hash 一致的幂等、工具失败回传和已提交部分的可见性属于执行器工作。预算耗尽暂停，不自动提取。
- 现有 note_ops 写回任务转向统一笔记工具；保留作用域、N/M 上限、可见可编辑和明确失败反馈。

## 4. 文档版本与提取迁移

当前权威：[data-model §§4.3–4.6](../data-model.md#43-analysis-与-analysisrevision)、[prompt-contracts §5](../prompt-contracts.md#5-从固定文档版本提取)。

- 引入文档级 AnalysisRevision manifest，保存小节版本及顺序；修改只新增变化内容。当前文档指针可更新，被引用版本不可覆盖。
- 结束讨论时先处理在途编辑，再固定完整 revision。ExtractionRun 必须带 analysis_revision_id，重试沿用同版本。
- kind/Span 映射归 ExtractionSection 与特定 run；不得在抽取时改写已经受保护的小节正文版本，不把旧映射套给新正文。
- 提取输入明确提供 section_id/revision；输出选择 section_id，替代旧 section_hint。候选增加完整出现范围 surfaces，与 slot_bindings 内的局部 surface 分开。
- Occurrence.spans 不能继续限制长度 1；完整匹配与槽位 Span 可共同存在，跨槽位不相交，但完整范围可包含槽位。
- 部分候选失败记录诊断，其余可以原子成功；全部无有效产物等情况才整体重试。不要沿用“任意槽位失败即整次重跑”。
- 同一 run 的提交幂等与新 run 追加 Occurrence 分开；维护式重抽保留来源，不自动重开已完成会话或新建复习项。
- 后续须新建版本化 prompt，不能原地修改旧 prompt 来伪造历史所用协议。

## 5. 历史与 SRS 迁移

当前权威：[data-model §0.1](../data-model.md#01-历史与当前状态)、[§7](../data-model.md#7-srs)、[ADR-039](../adr/039-history-protection.md)。

| 数据 | 后续实现原则 |
|---|---|
| 文档／小节 | 引用版本保护；无引用草稿有限保留；流式 token 不逐条版本化 |
| 用户意愿／合并 | 当前值可更新，加简短决定事件；抽取不能覆盖用户选择 |
| 笔记／批注 | 当前值可编辑删除；有限撤销与 Agent 操作审计 |
| reference | 暂停 ReviewItem，保留 ReviewState 和事件 |
| 改回 srs | 恢复已有进度，不消耗新卡配额；没有卡片才进入待建 |
| ReviewItem.retired_at | 非空当且仅当 status=retired；active/paused 必须为空，真正退役单向，不用于 reference 切换 |
| ReviewState / ReviewEvent | 当前投影可更新，复习事件追加；事件记录当时的 Occurrence |
| 运行与日志 | 当前状态更新，结束结果保留；秘密和隐藏推理不是业务持久化内容 |

已有以 retired_at 表示 reference 的数据需要显式迁移判别，不能直接清除旧退役标记或把所有历史退役都恢复。新目标 schema 不表示旧库可无迁移升级。

## 6. 后续验收同步清单

本节列验证意图，不替代阶段排期，也不宣称已有测试通过。后续负责人应据职责分配到任务包，重新核对依赖顺序和测试入口。

1. 准备中会话可从阅读器、素材卡片和全局队列打开，状态一致；同句多会话不覆盖。
2. 普通多选仍可讨论；automatic 明确选择且不以默认候选自动建卡。
3. 文档新增、改写、删除、重组实际提交；过期版本、重试和失败不会重复或误覆盖。
4. 上下文只注入当前文档一次，旧消息不被改写；摘要保留偏好和未解问题，工具协议不被截断。
5. 固定版本提取与在途编辑互斥；历史小节引用和快照清理保护正确。
6. 本次确认与 KP 全局选择分离；复用已确认 KP、零候选、部分确认、后续知识库变更均正确退出／保留会话。
7. reference 暂停，srs 恢复进度；新建配额与暂停恢复分开；复习事件不因换例句丢失。
8. kind/Span 按 run 存储，完整范围与多槽位 Span 正确；部分失败和全量失败的语义不同。
9. 用户决定、提取结果、Agent 副作用与复习事件的事务和幂等边界得到实际验证。
10. 保留原先 Unicode、来源版本、两层模型、词典安全、组件依赖和独立导出确认等未改变的验证要求。

data-model §9 保留 1–16 的编号但修订了含义，新增 17–20。旧 xfail 不能机械沿用；先按目标不变量重写验证目标，再由实现点亮。本轮没有点亮测试、完成任何阶段或承诺交互图谱／多句联合分析已实现。
