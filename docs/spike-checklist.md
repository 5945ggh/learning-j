# LearningJ 离线 Spike 待测清单

> 集中记录所有**不应靠推理拍板、只能靠数据收敛**的点。
> 全部为离线脚本可完成的实验，不写产品代码，不建数据库。
> 完成后回写 `LearningJ-plan-v5.md` §15 与 `prompt-contracts.md`。

---

## 0. 共用底座

### 0.1 评测集

**规模**：50 到 100 句，人工标注。这是所有实验的前提，也是委托 coding agent 开发时唯一能防止 prompt 质量回退的东西。

**构成建议**：

| 分组 | 句数 | 用途 |
|---|---|---|
| 口语密集（动漫台词） | 25 | 主力场景，A/B 类 |
| 书面语（轻小说地の文） | 15 | 长句、连体修饰、依存复杂度 |
| 文化互文密集 | 10 | C 类内容，`reference` 的判定 |

**复现对照组**：5 组配对句，同一语法点在远距离两处各出现一次，见实验 3。它是**标注属性而非独立分组**——配对句散布在上述三组之内，否则凑不出「远距离」。

**标注内容**：每句期望抽出的知识点（anchor + 应有的 salience），以及明确**不应**抽出的内容；是否进入复习由 triage 或无 triage 路径的默认规则另行决定。

### 0.2 通用指标

- **抽出率**：期望条目中被抽出的比例；
- **误抽率**：抽出条目中不在期望集内的比例（需人工判定，允许「合理但未预期」单列）；
- **复用率**：抽出的 anchor 中命中库内已有条目的比例；
- **抽象层级漂移率**：见实验 2。

## 1. 抽取执行路径：续轮 vs 独立调用

**待答问题**：`prompt-contracts.md` §5.4 的两条路径，默认该走哪条。

**做法**：同一批解析，分别用（a）同会话续轮、（b）冷启动独立调用执行抽取，比较三项指标。

**关注的已知风险**：同会话模型的自洽倾向可能导致

- **过抽**：把自己写过的全都抽出来，误抽率上升；
- **复用率下降**：沿用自己刚才的措辞，而非库内已有 anchor。

**判定**：若续轮的复用率显著低于独立调用，则默认路径改为独立调用，续轮只作为可选优化。**注意独立调用必须支持，这一条不因实验结果改变**——批量重抽依赖它。

## 2. 形态规范：锚点的抽象层级漂移

**待答问题**：未决事项 4（形态规范的具体写法与决策表）。这是整份文档中最不可能靠讨论收敛的一项。

**做法**：对同一语法现象在不同句子中的多次出现，看模型写出的 anchor 是否稳定。基线为 `prompt-contracts.md` §7.1 的临时规范。ADR-005 注一给的例子：

```
V辞書形 + ことができる
V + ことができる
〜ことができる
```

三个都合规，但指同一事物。

**指标**：**抽象层级漂移率** = 同一语言现象产出了多于一种合规写法的比例。

**变量**：

- 规范中是否附决策表（何时必须写出活用形限定）；
- 是否启用检索增强的 top-k 候选（`prompt-contracts.md` §5.3）；
- top-k 的 k 值（临时值 10）。

**产出**：形态规范决策表 v0。**这是本轮 spike 最重要的交付物。**

## 3. 跨句记忆的效果

**待答问题**：记忆注入是否真的避免了重复讲解，以及是否会矫枉过正（该讲的也不讲了）。

**做法**：用评测集的复现对照句——同一语法点在第 5 句和第 40 句各出现一次。分别在（a）注入已有 KP、（b）不注入两种条件下解析第 40 句。

**指标**：

- **重复展开率**：第二次是否又从头讲了一遍；
- **差异指出率**：当第二次用法确有不同时（如 `ている` 从进行变结果状态），是否指出了区别；
- **过度省略率**：第二次是否省略到用户无法理解的程度。

第三项是这个实验真正的价值所在——注入的失败模式不只是「没记住」，还有「记住了但因此讲太少」。

**注意**：MVP 的记忆注入只做词汇锚匹配（`prompt-contracts.md` §4.1），因此本实验的对照条件应与之一致。语法锚模式匹配不在本轮测试范围。

## 4. 子串定位

**待答问题**：`data-model.md` §1 与 `prompt-contracts.md` §5.2 的核心假设——模型给原文子串，后端 `find_all` 定位、经 sidecar 对齐推导 token 索引。

**做法**：让抽取输出 `surfaces`，在原句中执行 `find_all`，再用 SudachiPy 分词结果对齐，统计四态分布。

**指标**：Span 的 `aligned` / `partial` / `ambiguous` / `unaligned` 比例，另统计 `ExtractionRun.unresolved_surfaces` 比例；二者不得合并为一个失败率。

**关注**：

- **未解析 surface 与 `unaligned` 的成因分类**。这是本实验最重要的产出。surface 未命中的典型形态有：写成辞書形而非表层形、补上了省略的助词、把两处不连续的文字拼在一起、加了 `〜` 前缀；`unaligned` 则专指已命中但 token 侧无法对齐。每一种对应不同的 prompt 或 sidecar 修法；
- **`ambiguous` 的实际发生率**。设计假设是它很罕见（重复的短子串主要是助词类，而助词现象本就不该成为 KP）。若实测显著高于预期，需要重新考虑消歧字段——但**先看是哪些 anchor 触发的**，很可能是形态规范的问题而非定位机制的问题；
- 语法类 anchor（`〜なんて`）的子串往往横跨多个 token 且边界不齐，`partial` 率预期高于词汇类。这是可接受的，`partial` 不影响高亮显示。

**不再测**：字符偏移方案。已由 ADR-009 排除，理由是失败模式不可检测（整体偏移后仍能「对齐成功」，是静默错误），不是准确率问题。

## 5. 解析模块开关的默认组合

**待答问题**：`prompt-contracts.md` §1 的默认勾选。临时值：A 类全开，B/C 类六项。

**做法**：全开 vs 几种子集，看输出长度、内容取舍、以及模块之间是否互相挤占篇幅。

**指标**：**产出小节的 `kind` 分布 vs 勾选的模块集合**。这是本实验的核心可测量，其成立前提是 kind 集合 = 模块集合 + `takeaway` + `qa`（`data-model.md` §4.3），改动其一必须同时改另一。

**特别关注**：实录中那次面向低水平学习者的解析里出现了《こころ》互文——**好的解析本来就跨模块**。要验证的是关掉某个模块时，模型是真的不讲，还是把它塞进别的小节里。若是后者，说明模块开关是软约束，应据此调整 UI 措辞（「侧重」而非「只讲」）。

**顺带验证 `colloquial` 的音变部分**：它承担了原 `listening` 模块的内容（书面形与实际听感的落差）。用带 `user_question` 的听感类困惑测试，看模型是否把回应写进 `colloquial` 小节，还是新造了一个无法归类的小节。

## 6. 小节切分

**待答问题**：`prompt-contracts.md` §3.5——后端按段落／标题边界切分，第二段补 `kind` 与 `spans`。

**做法**：对实录级别的长解析做切分，人工判断切分点是否合理。

**关注**：切分粒度对 Occurrence 引用质量的影响。切太粗则卡背是一大段，切太细则一个知识点的解释被劈成两半。**这直接决定复习卡的可用性**，比它听起来重要。

---

## 7. 显著性判定

**待答问题**：`primary` 的判定是否稳定，条数是否可控。

**做法**：统计每句 `primary` 条目数的分布，与人工标注比对。

**判定**：若 `primary` 经常超过 3 条，说明指令不够强，需要在 prompt 中硬性限数；若经常为 0，说明第一段的收尾小节没写好，**问题在第一段而非第二段**——因此它是弱信号而非自动重跑条件（`prompt-contracts.md` §5.5）。

**范围提醒**：`salience` 现在只作用于批量与关窗兜底路径，用户主动触发抽取时走 triage 页（ADR-017）。因此本实验的优先级低于 v4 时的判断，但仍需做——批量解析是 A 类的主要使用形态。

该实验不再要求模型判定「一次性文化梗 vs 可复习形式」；凡进入 `candidates` 的条目都交给用户决定是否排程，未形成可复习知识点的内容应留在 Analysis 中。

## 8. 检索开关的影响

**待答问题**：实录中模型为确认 `よっと` 与《こころ》去查了原作与青空文库。联网检索会实质影响解析质量，尤其是文化互文类内容。

**排期**：检索不进 MVP，`retrieval_enabled` 字段位已留（`data-model.md` §4.1）。**本实验的产出无法影响任何 MVP 决策**，建议移入下方「不测」清单，待检索排期时再做。此处保留条目仅为记录问题本身。

---

## 9. 成本与延迟基线

**待答问题**：为 ADR-019 的配额与批量解析的并发上限提供数据。

**做法**：记录单句解析的 token 消耗（输入／输出分列）、抽取的 token 消耗、端到端延迟。

**推算**：A 类稠密使用（每天 30 到 50 句）下的日成本与月成本。这个数直接决定「BYOK 是否可接受」以及订阅打包的定价可行性。**本轮唯一直接服务商业判断的一项。**
