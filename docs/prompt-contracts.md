# LearningJ Prompt 与抽取契约

> 配套 `data-model.md`。本文规定第一段生成、第二段抽取、以及记忆注入的输入输出形状。**为什么**在 `adr.md`。
> **总原则**：第一段的讲解内容与语义组织不受固定机器契约约束；仅保留用于寻址的最小 heading-id 约定。一切知识点、Span 与其他机器可读语义结构仍由第二段产出（ADR-017）。
> 本文不含未决项。凡本次不实现或取临时值的内容均已明确标注。

---

## 1. 解析模块开关

用户勾选，可全选，可追加自由文本或整体修改。

> **模块 id 集合与 `AnalysisSection.kind` 严格一致**：kind 集合 = 本表九项 + `takeaway` + `qa`。后两项由系统产生，不进勾选列表。此包含关系是 `spike-checklist.md` 实验 5 的可测量前提，改动其一必须同时改另一。

| id | 名称 | 内容 |
|---|---|---|
| `overview` | 整句意思与骨架 | 直译与自然译的区别、修饰范围、成分切分 |
| `lexical` | 逐词拆解 | 词典形、词性、此处实际采用的意思 |
| `conjugation` | 活用与变形链 | 如 `サボる → サボって → サボっている`，及此处表进行／状态／习惯 |
| `grammar` | 句型与结构 | `〜なんて`、`〜ことができる` 一类的句型、句末形式、从属结构 |
| `particle` | 助词逐个解释 | 为何是 `で` 不是 `に`、`は` 是主题还是对比 |
| `colloquial` | 省略、口语与音变 | 助词脱落、句末截断、`んだけど` 类；以及**书面形与实际听感的落差**——促音、拨音、母音脱落、连读导致的词边界误判 |
| `register` | 语气与人际关系 | 距离感、称呼变化、敬语级别 |
| `culture` | 文化与互文 | 社会背景、时代梗、文学典故 |
| `translation_note` | 译文评价 | 随附译文牺牲了什么信息 |

### 关于 `colloquial` 的音变部分

它**不涉及音频输入**，是从文本可推导的音韵与形态推理。实录中的 `よっと` 案例即为此类：用户以文字说明「我听成了よ」，模型解释为什么该书面形在实际语流里会让学习者切错词边界。这对 A 类（主力素材为动漫、主要困惑来自听）是最高频的一类提问，必须有承载模块。

判断音频本身不在模型职责内，因此不设独立的 `listening` 模块。

### 默认组合（临时值，`spike-checklist.md` 实验 5 后回写）

- **A 类**：全部九项开启；
- **B / C 类**：`overview` + `grammar` + `colloquial` + `register` + `culture` + `translation_note`。

## 2. 第一段：解析生成

### 2.1 输入

```
[system]
  角色与总原则
  解析输出语言 = {output_language}          # ADR-024，与 UI i18n 无关
  勾选的模块 = {style_modules}
  用户追加要求 = {style_free_text?}

[context]
  作品 = {material_title}
  前文 = {prev_sentences}                    # 若干句
  原句 = {sentence_text}
  后文 = {next_sentences}
  随附译文 = {translation?}                  # 明确标注为参考而非标准
  用户困惑 = {user_question?}

[memory]
  已讲过的知识点 = {context_kps}             # 见 §4
  作品笔记 = {material_notes}
  学情画像 = {profile_notes}
```

**是否同时传入结构化解析信息（分词、活用、依存结果）**：第一段暂不传，待实验。第二段必须拿到分词结果，否则 Span 对齐无从做起。两段的输入不必一致。

### 2.2 关键指令

1. **随附译文只作参考**，分析优先从日文本身与上下文出发；译文与原文不一致时应指出。
2. **正文的讲解方式与小节顺序完全自由**，但为支持后续寻址，建议每个可独立引用的叶级小节使用带唯一 id 的 Markdown heading，例如：

   ```markdown
   # 知识点 {#knowledge}
   ## 〜ぐらい {#grammar-gurai}
   ```

   后端与抽取段使用 heading id 路径定位内容，例如 `["knowledge", "grammar-gurai"]`。heading id 只用于定位，不承载 `kind`、Span 或知识点语义；缺少或重复 id 时允许后端降级为段落定位并记录警告。
3. 同一叶级小节聚焦一个主要语言现象；相关的补充解释可以放在该小节内，但不要在多个兄弟小节中重复展开同一现象。模型仍可跨模块解释，不要求一个小节只属于一个语言学类别。
4. **必须以一个小节收尾**，点名本句最值得带走的 1 到 3 个东西。
5. 若 `user_question` 非空，必须正面回应它。

### 2.3 输出

带最小 heading-id 寻址标记的自由 markdown。落库时由后端切分为 AnalysisSection（见 §3.5）。

### 2.4 一次性解析是默认路径

**绝大多数 Analysis 的 `turn_count` 为 1，这是设计意图而非退化。**第一轮输出必须是独立可读的完整解析；会话是用户想追问时的升级项，不是常态。

理由是成本模型：「成本随用户实际学习的句数增长」若变成「随句数 × 每句会话深度」，A 类稠密使用下这个乘数很危险。

## 3. 会话形态

### 3.1 生命周期

```
生成解析 → [用户读，可追问 N 轮] → 用户点「提取知识点」→ 抽取 → triage → 决定 retention
```

**抽取由用户主动触发，该动作即会话终点**（ADR-017 决策五）。触发后 `Analysis.session_closed = true`，不再接受追问；需要补充时重新发起一次解析。

两条例外路径：

| 路径 | `extraction_trigger` | 行为 |
|---|---|---|
| 批量解析 | `batch` | 不开会话，抽取自动执行，产物直接进待确认收件箱 |
| 用户读完即关窗 | `background` | 后台补跑一次抽取，产物进待确认收件箱 |

这两条路径没有用户 triage，所有已抽取候选默认取 `retention = srs`；`salience` 决定 ReviewItem 的创建优先级。这是 `salience` 在有了 triage 页之后仍然必要的主要理由。

### 3.2 不依赖 tool calling

BYOK 下模型能力分布不均，多轮工具调用是高风险依赖。单句解析文档只有一两千 token 量级，不需要文件编辑工具。

**改写以结构化输出表达**：模型按小节 id 输出被修改或新增的小节，后端据此写入。弱模型也能做到。

真正的工具（查词典、检索已有 KP 库）可以有，但必须设计成**缺失时降级仍可用**。

### 3.3 追问轮的输入

```
[state]
  原句与上下文                                # 同第一段
  当前小节集合 = [{section_id, heading_path, kind?, spans, body_md, revision}, ...]
  最近 N 轮往返 = {recent_messages}

[user]
  {question}
```

### 3.4 追问轮的输出

```json
{
  "reply": "给用户看的对话回复",
  "section_ops": [
    {"op": "add",     "kind": "qa",      "surfaces": ["..."], "body_md": "..."},
    {"op": "revise",  "section_id": "…", "body_md": "..."},
    {"op": "merge",   "section_ids": ["…", "…"], "body_md": "..."}
  ],
  "note_ops": [
    {"scope": "material", "op": "add", "content": "..."},
    {"scope": "profile", "op": "replace", "note_id": "…", "content": "..."}
  ]
}
```

**排期切分**：`add` 进 MVP；`revise` 与 `merge` **本次不实现**（schema 第一天就要对，行为可以后长）。

### 3.5 小节切分

第一段输出的是带最小寻址标记的 markdown，切分为小节仍由**后端**完成，不要求模型输出 `kind` 或 Span。切分策略：

1. 优先按带唯一 id 的 heading 层级切分，并保留从根 heading 到叶 heading 的 id 路径；
2. 没有可靠 heading id 时，退化为模型自然产生的段落／标题边界；
3. 每个小节由第二段抽取顺带给出 `kind` 与 `spans`（见 §5.1）；
4. 切分失败时退化为单一 `overview` 小节——**这是合法的降级，不是错误**。Occurrence 仍可引用它。

## 4. 记忆注入

### 4.1 已讲过的知识点：检索，不是记忆

**这一项不由模型记住，由代码检索得出**（ADR-029）。

```
1. 取当前句 sidecar 的 lexeme 序列
2. 匹配已有 KP 的 lexical_anchors → 命中的词汇类 KP
3. 每条注入：anchor + Occurrence.brief（首次讲解要点）+ SRS 状态
```

**不按 `retention` 或任何学习意愿过滤。**判据只有「KP 存在 + 命中本句」。理由：本项回答的是「这个我讲过没有」这一确定性事实，而 `retention` 表达的是排程意愿。用户判为 `reference` 的文化互文，正是最需要在下次遇到时被注入的——否则模型会再从头讲一遍典故。

**本次不实现：高频语法锚的模式匹配。**因此语法类 KP 只有在下一次解析恰好又抽到它时才会再遇，**再遇率结构性偏低**。这是已知且接受的代价（`LearningJ-plan-v5.md` §8），不是抽取质量问题，实际使用时不要误判。

### 4.2 笔记注入

作品笔记按 `material_id` 全量注入（有条数上限，量可控）；学情画像全量注入。

### 4.3 写回

**`note_ops` 只在用户反馈后的模型回合中产生**（包括追问回合，以及用户对第一轮解析提出反馈后触发的补充回合）。第一轮解析本身只输出带最小寻址标记的 markdown，不夹带机器可读的 `note_ops`。

模型返回的 `note_ops` 是对持久化作品笔记／学情画像的**建议写操作**，由后端按槽位上限、作用域和 `replace` / `merge` 规则校验后落库：

```json
{
  "note_ops": [
    {"scope": "material", "op": "add",     "content": "..."},
    {"scope": "material", "op": "replace", "note_id": "…", "content": "..."},
    {"scope": "profile",  "op": "merge",   "note_ids": ["…","…"], "content": "..."}
  ]
}
```

**上限由后端强制**：槽位写满后，`add` 一律拒绝，模型必须改用 `replace` 或 `merge`。是否在当前仍未关闭的 agent 上下文中立即反映这次写回，暂不作为 MVP 的架构前提；后续请求至少必须能读取已持久化的笔记。不要在 prompt 里写「请你克制」——那不是约束，是希望。

## 5. 第二段：结构化抽取

### 5.1 输出 schema

抽取前先定位第一段中负责总结「本句最值得带走的东西」的 `takeaway` 小节。只有该小节点名的 1 到 3 个候选可以标记为 `salience = primary`；其余候选一律标记为 `secondary`。若找不到 takeaway，小节仍可抽取，但应将其作为弱信号报告，不把 `primary` 重新解释为模型主观重要性评分。

```json
{
  "sections": [
    {
      "section_hint": ["knowledge", "grammar-gurai"],
      "kind": "grammar",
      "surfaces": ["変化球"]
    }
  ],
  "candidates": [
    {
      "anchor": "〜なんて",
      "display_form": "普通形 + なんて",
      "surfaces": ["使うなんて"],
      "tags": ["grammar"],
      "salience": "primary",
      "section_hint": ["knowledge", "grammar-gurai"],
      "reuse_kp_id": null,
      "brief": "把某事拎出来带感情色彩地评论"
    }
  ]
}
```

### 5.2 字段规则

| 字段 | 规则 |
|---|---|
| `section_hint` | 从根 heading 到叶 heading 的唯一 id 路径；用于把抽取结果绑定到正文小节，不是自然语言摘要。没有可靠路径时为空数组，由后端按降级规则处理 |
| `anchor` | 必须符合形态规范。**优先复用候选列表中已有的 anchor**（见 §5.3） |
| `surfaces` | **非空的当前句原文子串数组，逐字照抄原句**。数组用于表达同一 anchor 在当前句中的多个独立出现位置；每个 surface 独立定位并生成 Occurrence。不给字符偏移、不给 token 索引。MVP 的 KP 抽取严格限于当前句；跨句解释可以出现在正文中，但不产生跨句 KP |
| `salience` | `primary` 仅给第一段收尾小节点名的 1 到 3 条；其余一律 `secondary` |
| `reuse_kp_id` | 复用候选列表中的已有 KP 时填其 id，新建时为 null |
| `brief` | 一句话要点摘要。落库进 Occurrence，供记忆注入与聚合视图使用 |

**模型不输出**（ADR-009）：

- 字符偏移与 token 索引——由后端从 `surfaces` 定位与对齐推导；
- `normalized_form / pos / reading_form` 三元组——由后端从 sidecar 取。模型会写出与 SudachiDict 字段不严格对齐的东西，污染别名表；
- `lexical_anchors`——同上，由算法推导。

**多 surface 的语义**：一个 candidate 代表一个 anchor 在当前句中的一种讲解，不为同一 anchor 的重复出现复制候选。每个 surface 独立定位；每个已定位的命中位置产生一条 Occurrence，并共享该 candidate 的 `kp_id`、`brief` 和 section 引用。单个 surface 多处命中时，按 `ambiguous` 规则为每处命中建立 Span / Occurrence；不同 surface 之间发生重叠时，各自独立定位，不合并、不静默丢弃。

**为什么是子串而非偏移**：偏移的典型失败是「整体偏了两位」，偏移后 span 仍落在句内、仍能与某个 token 对齐，是**静默错误**；子串的失败是「找不到」，100% 可由 `find_all` 检测，直接进 §5.5 的确定性重跑条件。多处命中的处理见 `data-model.md` §1，不需要模型给消歧字段。

### 5.3 检索增强的「选择」

抽取前先用模糊匹配从既有 KnowledgePoint 中取 top-k 候选，与规范一并交给模型，指令为：**复用其中之一，或在都不合适时按规范新建。**

这是把开放生成压回接近闭集选择的最便宜手段，也是别名表自然增长的来源。冷启动从 JLPT 语法表种子条目 + 种子别名起步。

`k` 的临时值取 **10**，待 `spike-checklist.md` 实验 2 回写。

### 5.4 抽取的两种执行路径

| 路径 | 说明 |
|---|---|
| **续轮**（默认快路径） | 在第一段的会话基础上新开一轮，同模型执行。优势是同一模型在同一语境里知道自己刚才指的是什么 |
| **独立调用**（必须支持） | 输入为「解析全文 + 规范 + 候选 KP」，不依赖会话历史 |

**第二段的 prompt 必须自足**，续轮只是它的一个快路径。这条约束一写死，抽取规范升级后的批量重抽、以及模型不支持长会话时的降级路径就都免费了。

**关于缓存**：缓存有 TTL，批量重抽必然冷启动，BYOK 下用户 provider 未必支持缓存。**缓存是优化，不是架构前提。**续轮的理由是质量而非成本。

**已知风险，待 spike 验证**：同会话的模型有自洽倾向，可能倾向于把自己写过的全都抽出来（过抽），并沿用自己的措辞而非库内已有 anchor（复用率下降）。

### 5.5 失败检测

以下为确定性检测，触发即**重跑抽取**（不重新生成解析）：

1. 输出非合法 JSON 或不符 schema；
2. `candidates` 为空而正文超过阈值长度；
3. 本次输出的全部 `surfaces` 均进入 `ExtractionRun.unresolved_surfaces`，即没有任何 surface 在原句中找到。

**弱信号**（提示而非自动重跑）：

- 抽出条数与正文长度比例异常；
- anchor 全部为新建（零复用）；
- **无任何 `salience = primary` 的条目**。

第三项不作自动重跑，理由：`primary` 为 0 说明第一段的收尾小节没写好，病灶在第一段，重跑抽取是对着错误的环节施药——重跑十次也抽不出第一段根本没写的东西。应提示用户**重新生成解析**。

## 6. 显著性与排程优先级

- `primary` → **优先创建 ReviewItem**（仍受每日配额约束）；
- `secondary` → 仍创建 KP 与 Occurrence，但不优先创建 ReviewItem，留在待建队列中。

`salience` 只表达候选在当前句中的重要性与无 triage 路径下的排程优先级；它不再与「是否适合复习」绑定。凡进入 `candidates` 的条目都默认 `retention = srs`，用户可以在 triage 或收件箱中改为 `reference`。

**适用范围**：仅 `extraction_trigger` 为 `batch` 或 `background` 的路径。用户主动触发抽取时走 triage 页，由用户逐条决定，`salience` 只用于排序与预选。

**不违反 ADR-019 的精神**：Occurrence 仍无条件全记、永不去重，`salience` 只改变 ReviewItem 的创建优先级，不改变 KP / Occurrence 的存在。

**待确认收件箱是未作用户决定的产物入口，不是历史浏览器。**不做未读计数，不做红点；用户在 triage 或收件箱中作出决定后，该候选从默认收件箱消失。已处理产物的历史查看由抽取运行记录、Analysis、KP 聚合视图等专门入口承担，不通过收件箱完成。

**收件箱按 KP 折叠**：同一 KP 的多条 Occurrence 显示为一行 +「再遇 n 次」，不平铺。ADR-019 的每 KP 一条只管住了 ReviewItem，管不住收件箱列表长度。

## 7. 形态规范

完整规范与决策表是 `spike-checklist.md` 实验 2 的交付物，尚未产出。

### 7.1 在此之前使用的临时规范

抽取段当前使用以下规则，实验 2 完成后整体替换：

1. 语法与句型：以 `〜` 开头或以 `V／N／A + ` 前缀标注接续，例 `〜なんて`、`V辞書形 + ことができる`；
2. 词汇与惯用搭配：写辞書形，例 `気にする`、`腹が立つ`；
3. 缩约与音变形：写变形本身，例 `〜ちゃう`、`〜とく`；
4. **同一次讲解中，同一语言现象只产出一条 anchor，不得同时给出多个抽象层级**（`V辞書形 + ことができる` 与 `〜ことができる` 二选一）。

### 7.2 什么不该成为 KP

规范除了「怎么写锚点」，还必须回答这个。已知锚不住的内容类型：

- 助词的口语脱落——是现象，不是形式；
- 「词边界误判」这类元技能；
- 不适合形成可复习知识点的文化背景、互文说明或元技能——留在 Analysis 中，不进入 `candidates`。

前两类留在 Analysis 里不抽取即可，这本来就是 Analysis 独立持久化的意义之一。
