# LearningJ 模型与 Agent 契约

> 本文规定生成、讨论 Agent、上下文组装与提取协议；实体和持久化以 [数据模型](data-model.md) 为准。决策理由见 [ADR 索引](adr.md)。
> 学习会话目标契约于 2026-09-08 更新，证据边界于 2026-09-09 补充（ADR-040）；阶段计划已按当前核心契约校准，task-packets 尚待单独同步。
> 版本化 prompt 文件仍是独立实现产物，本次不修改既有 prompt 文件。

## 1. 解析模块

| id | 内容 |
|---|---|
| `overview` | 整句意思、直译与自然译、修饰范围和骨架 |
| `lexical` | 词典形、词性、当前语境中的意思 |
| `conjugation` | 活用与变形链、当前表达的时态／体等 |
| `grammar` | 句型、接续、句末形式与从属结构 |
| `particle` | 助词的作用与选择 |
| `colloquial` | 省略、口语、音变，以及书面形与听感的落差 |
| `register` | 语气、称呼、人际关系与敬语 |
| `culture` | 文化背景与互文 |
| `translation_note` | 随附译文的取舍与偏差 |

用户可组合模块、补充自由要求，并在讨论中要求修改。临时默认值：A 类全开，B/C 类开启 overview、grammar、colloquial、register、culture、translation_note；最终默认值由实验 5 决定。

orthography／汉字方向尚未采纳为独立模块，学习对象身份与词典条目范围见产品规划 §15 第 19 项；当前不得自行增加 kind 或汉字 shape。

提取的小节 kind 集合为这九项加 `takeaway`、`qa`。kind 属于 ExtractionSection，不是初始生成的硬格式，也不与 KP tags 共用枚举。`colloquial` 可解释用户以文字描述的听感困惑，不承诺模型听过音频。

## 2. 初始生成

### 2.1 输入

- 固定指令：角色、输出语言、讲解原则与可用工具。
- 本次要求：模块选择、用户自由要求等。
- 原文上下文：作品名、原句、前后句、随附译文（明确标为参考）。首版每会话一句；未来多句需另行扩展输入与定位契约。
- 学习上下文：匹配到的既有 KP、作品笔记、学习者画像，来源及注入记录由后端保存。

第一轮是否主动附带全部形态结果仍待实验；需要时可通过本地工具查询。词典释义与形态事实必须标明资源来源，语义判断不能冒充算法验证。

### 2.2 输出与提交

初始目标是独立可读的完整解析，不要求用户先经历对话才能得到讲解。正文组织和顺序自由；建议可独立引用的小节有唯一 heading id，但缺失／重复不阻止生成成功。后端按可靠 heading、自然段落／标题、单一小节三级降级切分。

生成结果通过文档提交接口形成首个 AnalysisRevision：调用工具与直接返回 Markdown 都可由适配器进入同一提交路径。首次生成不要求同时返回候选 KP、kind 或 Span。

原文是定位基准；译文仅作参考；有用户问题时必须回应。文档应保留收尾 takeaway 小节，点名当前最值得带走的 1–3 项。讨论改变了内容时应同步更新总结；缺少总结按 §5.5 提示，不由前端补造。

流式未完成输出是草稿，不可被提取。切分失败的合法降级不是 provider 失败。

## 3. 讨论 Agent

### 3.1 页面与职责

桌面 Study 主区呈现当前解析文档，右侧对话区持续可用；窄屏规则见 DESIGN。用户可以提问，也可以要求缩写、扩写、纠错、改形态或重组。Agent 可以只交流，也可以调用工具修改文档；不要求每次回复都增加小节。

不再将 `add` 作为唯一允许的修改，不再把“一次追问”作为产品轮数限制。生成／讨论的运行次数、预算与会话阶段分开。用户结束讨论时提取确定版本，后续只重试提取；继续研究创建关联的新会话。

会话生命周期、普通多选、显式 automatic 模式、搁置与完成条件只在 data-model §4.1 定义，本节不另维护状态机。

### 3.2 工具契约

| 能力 | 工具的最小边界 |
|---|---|
| 读取文档 | 获取当前 revision、完整文档或指定小节 |
| 编辑文档 | 添加、替换、删除、移动／合并小节；提交目标 analysis_id、expected_revision 与结构化操作 |
| 原文与本地检索 | 读取原句／前后文、sidecar、导入词典、已有 KP；只读且返回来源 |
| 作品笔记／画像 | 列出、添加、修改、合并、删除；检查作用域、预期版本、槽位与长度 |

每个写工具返回成功／失败、受影响对象、提交后的 revision 与可读摘要。不存在、越界或过期目标必须报错；Agent 先刷新再修改。一次文档编辑提交是原子的，不把尚未完成的一组操作暴露为成功文档。

工具修改须对应用户当前请求或已授权的学习辅助范围；只读问题不隐式改变复习意愿。讨论工具不能绕过第二阶段直接创建 KP/Occurrence，不能擅自改变 retention、完成会话或触发外部导出。笔记修改对用户可见、可撤销或纠正。

执行器以 `(agent_run_id, call_id)` 去重并核对规范化输入 hash；同键同输入返回既有结果，同键不同输入报协议冲突。执行器记录副作用；工具返回失败不能被回复描述成成功。运行失败／取消时，先前已成功提交的编辑保留，页面显示已完成部分与剩余失败。

**Provider 能力边界**：优先使用原生工具调用。若 provider 不支持，可用结构化操作输出适配到同一执行器，但须通过工具语义、错误回传、幂等与多步编辑验证；不维持两套业务写入路径。两种方式都无法可靠执行时，明确提供只读问答降级，不伪装成可编辑 Agent。产品依赖的是可验证的工具操作能力，不依赖任一厂商的 response 类型。

### 3.3 每轮上下文组装

```text
固定指令：角色、规则、工具定义
早期对话摘要（如有）：用户偏好、已作决定、未解决问题
保留的历史：用户原始消息、可见回复、完整的必要工具交互
本轮运行上下文：原文、当前文档及 revision、相关笔记／画像／KP
本轮用户消息：用户本次原始输入
```

- 自动拼接内容与用户原始消息分别保存。每次请求移除历史中的旧注入块，当前文档只注入一次；不原地改写用户历史消息来实现重放。
- `[SYSTEM]` 等文本标记不构成真正的指令角色；固定规则与文档数据明确分离，具体消息布局由 provider adapter 实现。
- 成功编辑后，下一步 Agent 可读取新 revision；同一运行不能持续把编辑前文档当成当前状态。
- 历史工具输出可能含旧正文，应标明版本；当前文档是当前内容依据，历史对话保留的是当时的交流与决定。
- 应用不要求获取隐藏推理。provider 必需的续接数据由适配器按协议维护，不作为知识点内容或用户对话正文。

### 3.4 上下文与预算控制

1. 先去掉重复注入，保留最近对话；删除较早上下文前摘要用户偏好、否定意见、决定与待解问题，不能假定它们全写进了文档。
2. 工具调用及对应结果作为完整协议单元裁切；重试、续接与同一用户回合内多次调用由运行器处理。
3. 文档超过配置预算时，可读取目录／摘要并按需读取小节；定点修改仍以完整、已持久化的当前文档为准。提取阶段必须拿到确定版本的完整内容。
4. 上下文裁切不删除学习记录；不永久保存每轮完整注入副本。模板版本、目标文档版本和必要审计元数据保留。
5. 模型调用数、token 或费用预算达到上限时暂停并保留现场；不默认把预算耗尽解释为用户认可并自动提取。MVP 不提供由讨论预算触发的自动收尾；automatic 是创建时明确选择的另一种模式。

## 4. 学习上下文与笔记

### 4.1 KP 检索

从当前句的 sidecar lexeme 序列匹配 KP.lexical_anchors，注入 anchor、已有 Occurrence.brief 与实际 SRS 状态。不按 retention 过滤：reference 同样属于已经讲过的内容。

MVP 不实现语法模式自动匹配；语法再遇不能承诺达到词汇锚匹配的覆盖。检索是确定性来源，“某点是否讲过”不另交给散文记忆维护。

#### 学习信号的读取边界

- 按当前句的去重 Lexeme 集合批量检索可索引的 lexical_anchors、相关 KP 与必要摘要，不扫描全库证据或逐 token 发查询；按本轮上下文预算选择 Occurrence，保留 ID／来源与版本，不注入全部历史。
- “被讲解”“用户判断认识”“有导入支持”和“SRS 估计”分别标注。unknown 是用户当前明确否认；没有 KE 是缺少证据，不能生成“用户不会”的结论。不得用词汇覆盖高推导跳过必要讲解，或将人工否认写成模型已验证事实。
- KP → Lexeme 传播资格、用户优先级和时间求值只由后端按 data-model §§2.2–2.5 计算；检索命中或某次单词对齐不能替整个 KP／合并簇授予掌握。返回的动态信号带 as_of、来源与资格版本。
- Agent 只读取这些信号。聊天中“我认识／我不会”若需持久记录，由界面提供明确、带作用域的用户动作；工具不隐式写 KE、当前裁定、SRS 状态或活动统计。prompt 不能另维护传播／置信度合成规则。


### 4.2 作品笔记与画像

作品笔记按 material_id，画像按当前单用户范围检索；在槽位预算内注入。画像只承载偏好、困难和学习背景，作品笔记承载人物关系、语域和作品上下文。

Agent 通过同一笔记工具进行读取与修改，后端强制条数 N、单条长度 M、作用域与版本。写满时 add 被拒绝，可改用修改／合并；不以 prompt 中“请克制”代替写入约束。成功修改后后续请求能读取新内容，用户能看到修改反馈并编辑、删除。

## 5. 从固定文档版本提取

### 5.1 输入与输出

必需输入：原句及 sidecar、完整 AnalysisRevision（含每个 section_id、section_revision 和正文）、版本化的形态规范、top-k KP 候选。首版一句，字符偏移仍由后端推导。

示意输出：

```json
{
  "sections": [
    {"section_id": "已提供的逻辑小节 ID", "kind": "grammar", "surfaces": ["素人相手に"]}
  ],
  "candidates": [
    {
      "shape": "pattern",
      "payload": {"elements": [
        {"type": "slot", "id": "N1", "category": "N", "form": "none"},
        {"type": "literal", "text": "相手"},
        {"type": "literal", "text": "に"}
      ]},
      "surfaces": ["素人相手に"],
      "slot_bindings": {"N1": {"surface": "素人"}},
      "tags": ["grammar"],
      "salience": "primary",
      "section_id": "已提供的逻辑小节 ID",
      "reuse_kp_id": null,
      "brief": "以 N 为对象"
    }
  ]
}
```

每个输入小节必须有一个分类结果。section_id 只能选择输入版本中的 ID；revision 由后端从该文档 manifest 确定，不让模型猜。heading id 只用于最初切分，不再要求提取以可能歧义的 section_hint 寻址。

### 5.2 候选与定位

- shape 为 `pattern` / `lexical` / `entity` / `opaque`，payload 形状以 data-model §3.1 为准。
- 每个候选必有 `surfaces`，表示该知识点在原句中的完整出现范围；slot_bindings 的 surface 是其中的槽位实例，不能替代完整范围。
- 模型给语义判断和原文表层子串，不给 anchor、偏移、token 索引、lexeme 三元组或 span_id。`display_form` 是人工覆写，不由提取模型覆盖。
- 每个完整 surface 独立 find_all；多处命中时各产生一条带 ambiguous 完整 Span 的 Occurrence。不同候选可重叠，不为重复出现复制同一候选。
- pattern 的槽位在每个完整命中范围内定位，必须完整、有序且跨槽位不相交；完整 Span 可以包含槽位 Span。绑定无法唯一确定或不能满足模式约束时拒绝该次出现，记入 unresolved_patterns，不猜选一处。
- Occurrence.spans 有序包含完整匹配 Span 与成功的槽位 Span；同一个 span_id 不重复关联。slot_bindings 的值必须属于该数组。语法层 optional/repeat 等不连续模式仍未实现，多 Span 存储不等于 DSL 已支持它们。
- 普通 surface 命中但 token 不对齐可保留为 partial/unaligned；模式槽位若无法完成必要验证，拒绝该模式出现并记录原因。两种结果分开统计。
- `primary` 仅来自当前最终文档 takeaway 点名的 1–3 项，其余 secondary；不让模型决定用户的复习意愿。brief 必填，候选内容必须有可引用的解析小节。

### 5.3 身份召回与消解

先用原句与既有 payload 的字面量召回 top-k（临时 k=10），让模型选择复用或按规范新建。形式键已经存在直接复用；键不存在但有归一化近邻时，条件触发一次小调用询问复用或新建；无近邻直接新建。释义不参与身份判定。

复用只允许输入候选中的合法 ID，并由后端校验形状／模式兼容性；无效 ID 不得写入引用。实体唯一约束、合并与用户意愿保护见 data-model §3。

### 5.4 执行路径

`standalone` 必须支持，输入自足。`continued_turn` 可利用先前上下文，但必须明确注入同一固定文档版本，不从旧对话里的过时文档抽取。两条路径使用同版本提取规范，实验 1 比较质量后决定默认路径；当前保留续轮为可选快路径。

提取不调用编辑文档或修改画像的工具。失败只重试同一文档版本，不重做初始生成。用户需要修改解析时创建新的关联会话；维护式重抽不自动进入用户学习队列。带用户 hint 的重抽、已成功产物的弃用及同会话回到 discussion 尚待产品规划 §15 第 20 项决策，不能自行解释为已有 retry 权限。

### 5.5 失败与部分成功

整体失败并允许自动重试（最多追加两次尝试）：

1. 输出不能通过 JSON／schema 校验，或 sections 无法完整绑定输入版本。
2. 正文超过配置阈值但 candidates 为空。
3. 没有任何候选可以形成有效 Occurrence，包括全部 surface 未命中或全部模式绑定失败。

个别 surface／模式失败时记录 unresolved_surfaces、invalid_patterns、unresolved_patterns；其余有效候选可原子提交。该规则取代“任一槽位失败就整次重跑”的笼统表述。短文零候选可以合法完成，返回明确结果交用户完成会话。

弱信号仅提示：条数与正文比例异常、全部新建零复用、没有 primary。缺少 takeaway 时建议回到新的编辑会话修订文档，不靠反复提取修复不存在的总结。

## 6. 确认与排程边界

提取成功不等于用户确认；复习意愿与实际卡片状态分开。所有模式的默认候选均不自动建卡，用户明确选择后才进入配额排程。salience 用于候选排序与新卡待建优先级，不表示是否适合成为 KP。

本次会话确认、知识库全局意愿与历史快照的唯一写入规则见 data-model §§3.1、4.2、7；前端不得以 KP 当前 default 数量推导会话完成，也不得因知识库变更重新打开旧会话。“排除本次候选”与 reference 不同，目前未新增排除结果或优先级覆盖；仍须确认当前 run 全部不同 KP，或搁置会话。提取产物的 salience、brief、Span 与来源不可在确认界面原地修改。

## 7. 模式语言

结构化 pattern 与校验原则见 [ADR-034](adr/034-pattern-language.md)。当前 category：N / V / A-i / A-na / Clause / Any；form：none / base / continuative / te / past / negative / attributive / conditional。

### 7.1 临时规范

实验 2 尚未冻结完整决策表。无法表达的构式使用 opaque + model_chosen；模式校验失败降级时使用 validation_failed，两者分开统计。opaque 的临时书写约定：语法采用 `〜` 或接续前缀；词汇／惯用搭配用辞書形；缩约写变形本身。同一次讲解的同一现象不输出多个抽象层级。

字面量顺序、槽位范围与 POS/category 相容性由后端校验；form 能校验时检查，无法可靠判断时记录 warning。零槽位字面量若对应单一 lexeme，应采用 lexical。枚举、POS 映射、严格度与序列化算法都版本化，不在本次文档修订中假定实验已经完成。

### 7.2 候选边界

可被解释、定位并形成知识点的内容进入 candidates，由用户决定是否复习；无法形成这种对象的背景说明、词边界误判等元技能留在文档。reference 是用户意愿，不是模型对“文化内容”的分类标签。查词、笔记与 Annotation 不绕过提取自动创建 KP。
