# RF-02 素材库与阅读器前端重构实施指导

状态：2026-09-15，RF-02 三个可体验节点已实施并完成本地验收；后置能力仍按停止点保留。

RF-01 已完成 EPUB reader-ready 基础能力并正式收尾。本动作不重新打开 RF-01 的 parser、publication identity、projection/version、安全资源服务或 Sidecar 边界；若实施中发现新的 RF-01 correctness 问题，单独记录并报告，不借本次视觉／结构重构顺手改变后端契约。

本动作是限定在素材库与阅读器的中等规模界面/状态整理，不是全仓重构。按三个可体验节点交付，不以所有 controller 拆完作为首次展示的前提。

本动作目标是将当前用于占位和功能验证的前端界面，收敛到 `DESIGN.md` 已确定的信息架构、reader chrome、素材卡片、响应式和视觉语言，并在此过程中降低旧 `MaterialWorkspace` 等集中组件的维护成本。

## 输入与权威

实施前按实际触及范围阅读：

* `AGENTS.md`
* `DESIGN.md`，尤其“信息架构”“视觉语言”“应用外壳与素材界面”“阅读器 chrome 与工具层”“无障碍”“响应式行为”“句子语境与多选”“实现约束”
* `docs/reader-foundation/README.md` 当前派发入口
* 本文件及 [标准开工指导](README.md)、[测试标准](../reader-foundation/testing-standard.md)
* `docs/data-model.md` §0、§8，仅在使用已有 Material / Sentence / Sidecar / publication 状态时核对，不为本任务修改领域契约
* RF-01 当前交接记录，仅用于理解 reader-ready、publication surface、无 Sidecar 等既有能力边界

`DESIGN.md` 是此次用户界面的权威来源。现有 JSX、CSS、旧 mockup 与当前截图只代表实现基线，若与现行设计契约冲突，应调整实现而不是反向修改契约。

若发现 `DESIGN.md` 与当前数据／API 契约存在真正冲突，停止受影响的功能分支并报告具体文件、字段和冲突；不要为了完成视觉稿自行增加领域状态。

## 目标与完成定义

完成后应形成一套可以继续扩展的前端基础，而不是只完成一次换皮：

1. 应用外壳、素材库和阅读器使用一致的语义设计 token，不依赖散落的硬编码颜色、blur 和 shadow 建立层次。
2. 素材库以封面和内容为中心，移除占位时期堆叠在 MaterialCard 上的过多导航／学习操作。
3. Reader 从当前“通用 sidebar + 内容”调整为独立 reader chrome：

   * 顶部 reader toolbar；
   * 左侧 reader rail；
   * 可折叠稳定 panel 区；
   * 中央阅读内容 surface。
4. Reader 的三个稳定 panel slot 固定为：

   * 查词／词典；
   * 句子操作；
   * 当前材料会话列表。
5. 目录、搜索、排版、标注管理等属于 reader tool，而不是稳定 panel slot；不得继续与上述三个 slot 共用一套业务枚举。
6. EPUB publication 继续使用 RF-01 的受控 iframe／HTTP surface；Reader 不复制或重写 EPUB 解析、安全与 canonical projection。
7. 旧 `MaterialWorkspace` 的集中状态开始拆离，使内容获取、token、lookup、decision 等生命周期不再全部由一个大型视图组件隐式协调。
8. ≥1180px、760–1179px、<760px 三类宽度均有明确可用布局；不要求三种尺寸视觉完全相同。
9. 当前已有阅读、查词、Sentence/token、素材打开等行为继续工作；本动作不以“视觉重构”为理由删除已有能力。

达到上述条件后即可交付。知识库、解析队列、学习中心和 Study 的全面视觉重构不属于本动作。

## 非目标

本动作明确不负责：

* 修改 EPUB parser、sanitizer、publication manifest 或 projection version；
* 新增后端字段、状态机或 API；
* 实现新的 AI / SRS / KnowledgePoint 能力；
* 为整个应用一次性重做所有顶级页面；
* 完成完整 selection/context-menu、批量句子学习或句子合并等尚未独立派发的功能；
* 引入新的全局状态管理框架；
* 引入 TanStack Query 等 server-state 框架来替换当前 repository 边界；
* 为目录整齐而批量搬迁无关组件；
* 做 Apple UI 的像素级复制、毛玻璃拟真或复杂装饰动画；
* 建立完整视觉截图 CI 基建。

可以为后续 selection、多选、context menu 等能力形成正确的组件和状态接缝，但不得为了“顺便做完设计稿”扩大产品范围。

## 前端架构方向

### 1. Screen 保持薄装配

`ReaderScreen` 继续负责：

* 读取 route material id；
* 获取或选择当前 Material；
* 根据 material kind 选择正文 surface；
* 装配 Reader workspace；
* 处理顶层 loading / material-not-found 等页面状态。

不得让它重新承担 token lookup、iframe DOM、panel 内部交互或字典请求细节。

`LibraryScreen` 负责页面装配、模式／筛选和素材集合；单个素材视觉与局部操作仍由独立组件负责。

### 2. ReaderWorkspace 成为 Reader 的状态边界

允许新建或逐步形成一个 reader workspace/controller 层，名字可按现有目录实际调整。

建议职责：

* 已展开的 stable panel 槽位集合，以及窄屏当前呈现的槽位；
* transient reader tool；
* 当前 material 视图状态；chapter 由一个 controller 唯一持有，workspace 通过同一数据/callback 接线，不复制章节状态；
* 单一 Reader selection state；
* 组装 lookup / token / material-session 等 controller；
* 把数据与 callback 传给 shell-independent panel。

不得把这些状态塞进 router query 参数来充当业务状态机。

选择状态遵守“单一权威”原则。实现形式不强制冻结，但应能表达：

```ts
type ReaderSelectionState = {
  mode: 'single' | 'multi'
  token: TokenRef | null
  selectedSentenceIds: string[]
}
```

具体字段可按现有类型调整。

约束：

* 当前上下文句能由 selected token 推导时，不另存第二份相同状态；
* 单句直接操作可以是 `token = null` + 一个 Sentence；
* multi mode 必须显式进入，不由普通点击猜测；
* 本轮若尚未实现完整多选行为，可以只建立状态接缝，不制造假 UI。

### 3. ReaderShell 只负责布局

目标结构可参考：

```text
ReaderScreen
└─ ReaderWorkspace
   └─ ReaderShell
      ├─ ReaderToolbar
      ├─ ReaderRail
      ├─ ReaderPanelRegion
      │  ├─ DictionaryPanel
      │  ├─ SentenceActionsPanel
      │  └─ MaterialSessionsPanel
      └─ ReaderContentSurface
         ├─ EpubPublication
         └─ TokenizedTextSurface
```

名称不是契约；职责边界是契约。

`ReaderShell` 不直接：

* 请求字典；
* 操作 Sidecar；
* 读取 route；
* 解析 EPUB；
* 创建 StudySession；
* 持有词典领域状态。

### 4. Stable panel 与 reader tool 分开建模

不要继续使用一套 `outline | queue | display | ...` 枚举表示所有 reader 侧边内容。

建议至少在类型上区分：

```ts
type ReaderPanelSlot =
  | 'dictionary'
  | 'sentence-actions'
  | 'material-sessions'

type ReaderTool =
  | 'outline'
  | 'search'
  | 'display'
  | 'annotations'
```

stable panel：

* 是阅读时持续存在的工具工作区；
* 可以折叠；
* 在共享 panel region 内可独立展开/折叠，槽位不互斥；窄屏可以只呈现当前槽位，但切换呈现不能删除其他槽位的数据与状态；
* 宽屏优先位于 rail 与正文之间。

reader tool：

* 由 rail / toolbar 触发；
* 可使用 popover、dialog、临时 panel、floating toolbar 等；
* 打开目录或排版设置不应破坏词典／句子操作状态；
* 不因此增加第四、第五个稳定 panel slot。

槽位 ID 的 union 只定义身份，不表示只能选中一个。展开集合与窄屏当前槽位分开表达；点击某槽位只切换该槽位。关闭临时工具不清空稳定面板状态。窄屏查词仍一步可达。

### 5. EPUB content surface 去 chrome 化

`EpubPublication` 保留：

* publication repository；
* chapter 加载；
* iframe 生命周期；
* RF-01 trusted-document 验证；
* chapter failure / retry；
* chapter DOM 与 publication adapter 必需逻辑。

应尽量移出：

* Reader 顶级标题；
* 与全局 Reader 重复的上一章／下一章 chrome；
* 独立“卡片”外框；
* reader rail / toolbar 视觉责任。

章节名称、上一章／下一章、返回素材库等 reader 级操作由 Reader chrome 统一呈现；通过唯一 chapter controller 的状态和动作接线。可以保留现有状态拥有者并向外暴露接口，也可以完整迁移拥有者，但不得两处 useState 互相同步章节。

面板开关、工具切换、主题及响应式容器变化不得无故重新挂载 iframe 或重置章节/当前阅读位置；语言工具的 selection、结果及在途请求也不能因换布局而重置。切换素材时则应清理旧素材作用域状态。此处保护同次阅读的交互稳定性，不新增刷新/重启后的持久恢复。

不能为了视觉重构改变：

* iframe sandbox；
* publication endpoint；
* trusted marker；
* CSP；
* controlled DOM；
* RF-01 source/projection identity。

### 6. MaterialWorkspace 渐进拆分，不做机械拆文件

当前大型 workspace 的首要问题是状态生命周期混合，而不是文件行数本身。

优先抽离 controller / hook：

* material / Sentence；
* Sidecar / content index；
* token selection；
* dictionary lookup；
* Lexeme decision。

其中 lookup/decision 如已有多个互相约束的 `useState`、AbortController、request generation、retry/conflict 状态，可以使用局部 reducer 或 controller hook，使非法组合更难出现。

不要：

* 先按“API / model / ui”机械拆三层；
* 为了减少单文件行数制造大量一行 wrapper；
* 把 repository 逻辑重新写进视图；
* 在本动作里引入全局 store。

旧 `MaterialWorkspace` 可以在迁移期间继续存在，但交付时不应继续作为 Reader 的完整 shell + domain controller + content renderer 三合一入口。

## 视觉基础

### 语义 token

建立或整理统一语义 token，至少覆盖：

```text
canvas
shell_surface
translucent_surface
opaque_surface
page
grouped_surface
secondary_grouped_surface

text
secondary_text
border
divider
shadow

algorithm
ai
warning
success

context_sentence
multi_selection
annotation
occurrence
```

组件优先使用语义变量，不硬编码浅色主题值。

当前浅色基线遵循 `DESIGN.md`：

* 象牙色 canvas；
* 暖白阅读 page；
* 中性灰文本；
* algorithm / dictionary 为克制蓝；
* AI 为克制紫；
* warning / success 低面积使用。

不要把 algorithm / AI 色用于普通导航选中态。

现有应用已有 light/dark 主题切换与系统偏好选择。新增语义变量必须提供可读的暗色值或等价回退，保留现有切换、对比度和焦点可见性；两种主题均检查素材库和阅读器。完整暗色视觉精修与主题包后置，不能以此放任现有暗色状态退化。

### 表面与阴影

Web 版在没有 `backdrop-filter` 时仍必须成立。

普通：

* sidebar；
* MaterialCard；
* library section；
* reader page；
* navigation selected item；

主要靠：

* 留白；
* surface tone；
* 1px border；
* 排版层级；

表达。

明显 shadow 只用于真实覆盖关系：

* popover；
* context menu；
* modal/dialog；
* floating toolbar；
* 临时覆盖 reader 的 panel；
* drag object。

禁止继续用 hover elevation 作为普通素材卡片反馈。

### 圆角与排版

允许形成分层 token，例如：

* control：约 7px；
* action：约 10px；
* grouped surface：约 14px；
* reading page：可更大但克制。

正文／来源引文优先日文 serif stack；控件和 metadata 使用 sans-serif stack。

不要为了字体效果在本动作引入不可审查的远程 webfont 依赖。

## 素材库重构

### Library 页面

素材库继续提供“书目 / 视听”模式。

本动作重点完成书籍模式；音视频模式只需保持：

* 共同的页面间距；
* header；
* 搜索／导入入口；
* 模式切换；
* 卡片归属与基础 surface 语言。

不要借此重做播放器。

### Book MaterialCard

书籍卡片目标：

* 封面占据主要视觉面积；
* 下方显示 title；
* 有 author 时显示 author；
* 只展示一至两项真正重要的 metadata；
* 活动学习会话数量可作为低强调度信息／入口；
* 三点菜单承担管理操作。

默认：

* 无明显阴影；
* 无 hover 上浮；
* 无封面夸张 zoom；
* hover 只改变 border / background / tonal contrast。

普通主点击：

**直接进入 Reader。**

不要继续要求用户必须先进入 MaterialDetail 才能阅读。

三点菜单可提供：

* 材料信息；
* 元数据编辑入口；
* 重新处理等已有合法材料操作；
* 其他当前已经存在且属于材料管理的操作。

不要把以下内容并列成 MaterialCard 的主要按钮：

* 知识库；
* Study；
* 解析队列；
* 多个学习阶段入口。

这些能力通过真实信息架构进入，而不是让一张素材卡片成为第二套主导航。

`MaterialDetailScreen` 可以保留为材料信息／管理页面或 dialog 入口；不要求删除。

### 真实能力边界

开工按当前 repository/API 核对封面、author、会话数量/列表、元数据编辑、重新处理和其他管理操作是否真实可用。真实材料缺少能力时隐藏动作或显示明确不可用说明，不显示假计数（包括用 0 代替未知）、假成功或无实际作用的可点击菜单。fixture 仅用于明确隔离/标注的演示与测试，不混入真实材料的事实。

已有可用行为保留；设计中尚未实现的动作不成为本轮补后端的要求。稳定槽位可以展示真实的 unavailable 状态，但不能借“保留三个槽位”伪造会话、查词或句子操作。

### 会话入口

已有真实会话列表能力时，用户仍需能在不打开 Reader 的情况下进入该材料的会话列表；未接入时遵守上述真实能力边界，不要求在本轮实现会话后端。

可以使用：

* 活动会话计数；
* context / overflow 中明确入口；
* 卡片 metadata 区的低强调 affordance。

但不要与“打开书籍”的主要视觉动作竞争。

## Reader 重构

### Reader chrome

进入 Reader 后：

* 应用级 sidebar 默认退出视野；
* 顶部 toolbar 提供返回应用层级、文档信息与阅读环境操作；
* 左侧 reader rail 负责材料内部工具入口；
* 正文始终是视觉主体。

Reader 不应看起来像“AppShell 里又塞了一张 dashboard card”。

### Wide layout：≥1180px

优先结构：

```text
rail | optional stable panel stack | reading surface
```

要求：

* panel 打开时正文仍保持稳定可读；
* 尽量减少当前句／当前视口的横向跳动；
* 阅读列宽有合理最大值；
* panel 不能靠覆盖正文的重 blur 建立层次。

### Compact layout：760–1179px

允许：

* rail 缩窄；
* 查词按 DESIGN 使用锚定 popover；其他稳定槽位可以按空间使用 overlay/drawer，不把任意 drawer 替代紧凑布局的查词规则；
* 非核心 reader tool 收入 toolbar；
* Reader 正文优先保留宽度。

无论具体形态如何：

* dictionary 一步可达；
* Sentence actions 一步可达；
* material sessions 一步可达。

### Narrow layout：<760px

不要求持续显示左 rail。

stable panel 可变成：

* bottom sheet；
* full-width dialog；
* 单一 panel surface 内的 segmented slots。

必须：

* 提供明显关闭／返回；
* 保留阅读位置；
* 控件至少约 40px 可点击区域；
* 不依赖 hover；
* dictionary 仍保持一步可达。

### Reader toolbar

负责：

* 返回素材库／应用层级；
* material / chapter context；
* 上一章／下一章等文档导航；
* 阅读呈现工具入口；
* 必要的溢出操作。

不要把“加入 AI 学习”做成 toolbar 常驻的大型彩色 CTA。

AI 学习属于 token／Sentence context 或 Sentence Actions 中的有意操作。

## Sidecar 与 reader-ready 状态

RF-01 已允许 EPUB 在没有 Sidecar 时 reader-ready。

因此：

* publication 可读时必须继续允许阅读；
* dictionary / Sentence actions 等确实依赖 Sidecar 的能力显示 disabled/unavailable 状态；
* 清楚说明“正文可读，语言工具尚不可用”；
* 不把 Sidecar 缺失显示成 EPUB 导入失败；
* 不伪造 token、Sentence 或 lookup 结果。

非 EPUB 的当前行为继续保留。

## Shell-independent components

以下功能组件不得依赖具体 shell：

* Dictionary panel；
* Sentence actions；
* Material sessions；
* token controls；
* Sentence context；
* lookup result；
* MaterialCard 核心内容。

组件通过 props / callbacks 接收：

* 当前作用域；
* 数据；
* loading/error 状态；
* selection；
* actions。

由 Reader shell 决定某个 panel 在当前断点是：

* inline region；
* drawer；
* bottom sheet；
* dialog；
* popover。

不得让 Dictionary 组件自己检查 viewport 后决定产品结构。

## shadcn / UI primitive 使用策略

沿用 Tailwind + 当前 UI primitives。

若复杂交互确实需要：

* DropdownMenu；
* Dialog；
* Popover；
* Tooltip；
* Sheet；

优先复用现有 primitive；新增 shadcn/headless primitive 的第三方依赖仍须有明确授权，不能仅凭本方案的可选路线视为任意加包许可。确需新增时列明包名、用途及为何现有能力不足；获授权后同步 lockfile。

不要：

* 为了“迁移到 shadcn”批量重写现有简单 Button/Badge；
* 一次导入整套无关 primitive；
* 让第三方默认视觉覆盖本项目 token；
* 为单个视觉效果引入大型 UI framework。

新增依赖需在交付记录中说明用途。

## 无障碍与交互要求

本动作至少保护：

* icon button 有 accessible name；
* Escape 可关闭临时 panel / popover / dialog；
* 关闭后焦点尽量返回触发点；
* drawer / dialog / complementary region 使用适合的语义；
* 状态不能只靠颜色表达；
* keyboard focus 清晰可见；
* `prefers-reduced-motion` 禁用非必要动画；
* touch 路径不依赖 hover；
* 紧凑布局点击区域不少于约 40px。

若当前 token lookup 已支持键盘路径，重构后不得退化。

selection/context-menu 的完整平台行为可后置，但重构不能通过 `preventDefault` 全局破坏浏览器复制、输入框或 Yomitan 既有手势。

## 写入范围
