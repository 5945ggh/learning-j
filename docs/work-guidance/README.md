# 本地工作 agent 标准开工指导

状态：2026-09-14 生效。此目录保存执行指导与本地采纳记录；产品范围和当前任务仍从 [reader-foundation](../reader-foundation/README.md) 进入，不建立第二套任务台账或字段契约。

## 文档放在哪里

- `docs/reader-foundation/`：阅读器范围、交付安排、测试标准、研究与原始咨询材料。现有 RF-01 纲要和 advice 保留原路径，避免破坏已发送的引用。
- `docs/work-guidance/README.md`：跨任务共用的开工方式，即本文件。
- `docs/work-guidance/<任务ID>.md`：本地采纳决定、执行边界、开工补充与交付记录。当前为 [RF-02](RF-02.md)。每个任务只有这一份本地记录，不再在纲要复制一份状态。

后续新增任务沿用这个分工；不提前创建空任务文档，不搬动历史 task-packets、研究附件或报告。远端 advice 保持原文，本地修正写进任务指导并指出对应段落。

## 开工时需要的输入

用户只需给出任务 ID 和本地任务指导路径。任务指导应链接纲要、advice（如有）、相关契约和测试标准，agent 自行按需读取，不要求用户重述仓库已有规则。可附真实测试书的本地路径、期望体验或明确排除事项；缺少真实书不阻止隔离技术验证，但不能宣称真实书验收完成。

执行 agent 先读根 `AGENTS.md`、当前任务入口、本文件和指定任务指导。本地采纳记录明确了 advice 中哪些建议适用；它不覆盖未获授权的字段契约。不要只把 advice 当施工单，也不要全量读未来阶段包。

## 本地核对与执行

1. 记录当前 HEAD、分支和相关工作树改动，识别已有文件归属；不覆盖、回滚或顺带提交他人工作。比较远端事实与本地相关代码即可，不重复全库调查。
2. 远端缺少确切 SHA 时，保留“调查时提交未知”。现在查询到的 `origin/develop` 或 `ls-remote` 只能证明现在的状态，不能倒填远端历史基线。用本地 HEAD、点名符号和相关差异建立本次执行基线，无须因此把整份咨询退回重做。
3. 在任务指导追加短计划：改哪些职责、先做什么、选择哪些验证、何时停止。纯重构先说明搬迁理由和保留行为；缺少关键回归时先补，再移动。任务已授予的普通技术取舍直接执行。
4. 若需改变契约，先完成任务明确授权的独立契约对齐步骤，记录决定和依据，再实现。只改列出的文件/章节，不用改文档为回归开脱；未解决的产品语义仅暂停相关分支。
5. 前后端可以由同一任务覆盖。需要子代理时按明确文件/职责划分，告知共享工作树且不可回退他人修改；接口依赖未定前不要让两个 agent 各造一套类型或定位身份。
6. 按[测试标准](../reader-foundation/testing-standard.md)运行受影响测试与静态检查。每次有意义的视觉修改检查实际界面。交付前用变更协调角色检查相关契约差异，不把非阻塞建议扩成新阶段。

同一切片中的修复、调试与视觉迭代无需反复远端咨询。新增依赖仍需明确授权；提交、推送、数据库删除及范围扩展按用户现有授权处理，本文件不新增这些授权。

## 交付记录

在任务指导中追加：用户动作与结果、主要改动、实际命令和结果、截图/启动方式、未验证项。标明技术验证与真实素材体验的区别；没有运行的检查不得写成通过。达到任务停止点就交付，不继续未来功能，不重写原始 advice 或历史报告。

## 可复制的标准派遣语

> 请按 `docs/work-guidance/<任务ID>.md` 实施该任务。先读根 AGENTS.md 和标准开工指导，并按链接读取纲要、咨询原文及相关契约。核对当前工作树后，按已接受的本地决定完成契约对齐、必要局部整理、实现和验证；普通技术取舍直接处理，不扩大为全仓重构。保留已有修改，达到用户动作停止点即交付，并将结果补入该任务指导。
