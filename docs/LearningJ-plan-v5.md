## 0. 主张

**方便地获得 AI 解析，保存可讨论、可修改、可回看的讲解，把其中的知识点沉淀并使其再遇。**

查词、注音和基础翻译是阅读底座；AI 的价值在于语境化讲解、用户讨论产生的补充，以及长期学习产物。一次完整解析是默认起点，用户可以直接进入提取，也可以继续讨论。

## 1. 受众

| 人群 | 主要需求 | 产品含义 |
|---|---|---|
| A：零基础沉浸学习者 | 稠密解析、低门槛理解，难以自行验证 AI | 算法与 AI 来源分开；完整首稿与费用控制必要；易安装发行版决定实际可达时间 |
| B：已有 Yomitan / asbplayer / Anki 工作流的沉浸学习者 | 卡住时解析、积累、再遇与互操作 | MVP 的主要可达用户；BYOK、本地数据和导入导出有价值 |
| C：高水平语用文化读者 | 背景、互文、批注与检索，未必需要复习 | 作为 B 的留存阶段；reference 在 MVP，主动发现可疑句后置 |

不排除应试用户，但不为与沉浸路径无关的考纲、题库和模拟卷单独优化。解析输出语言可配置，UI 多语言另行排期。

## 2. 交互内核

阅读者选择值得深入理解的原文，创建一次**学习会话**。会话先异步准备完整解析，随后允许讨论与编辑；用户结束讨论，再提取和确认知识点。阅读不必停下来等待模型。

A 类可能为大量句子创建会话，主动点击不再是可靠的价值筛选信号；成本预算与新卡配额因此独立于点击频次。B 类使用较稀疏。C 类的系统发现能力后置，不预先全量 AI 分析材料。

“语法、搭配、语域”等是可重叠标签；anchor_shape 是结构化 payload 的格式，不作为学习内容的互斥分类。

## 3. 阅读、学习会话、知识库与复习

**素材统一抽象**：有序 Sentence + 可选时间戳 + 定位信息。解析、提取、知识点与复习逻辑不按素材类型另起一套；具体资源播放／返回适配留在边界层。

| 入口 | 层级 | 用户任务 |
|---|---|---|
| 主页 | 顶级导航 | 当前仅作导航占位；默认内容、排序与可进入的聚合范围仍待 §15 决定，暂不把 `return_position`、队列数量或任何学习状态承诺为首页默认内容 |
| 素材库 | 顶级导航 | 选择材料、发起阅读与学习会话 |
| 阅读器／（音视频）播放器 | 工作区 | 阅读查词、播放、标注原文 |
| 解析队列 | 顶级导航 | 查看尚未完成的会话，准备中即可打开；全局入口可筛选全材料的同一批会话。导航标签为“解析队列”，实体仍称“学习会话” |
| AI 学习页 Study | 工作区 | 主区阅读与编辑解析，右侧与 Agent 交流，结束讨论后提取并确认 |
| 学习记录 | 学习中心内子视图 | 回看已完成或搁置会话、对话与提取来源 |
| 知识库 | 顶级导航 | 查看知识点、来源、关系、复习意愿与实际学习进度；支持全局和材料范围 |
| 学习中心 | 顶级导航 | 承载新卡引入与到期复习的统一队列、学习记录与素材维度入口；“复习”是其到期段落 |

“解析队列”取代原先过宽的“收件箱”称呼；早期的宽泛队列标签不再对应任何界面标签，且与“学习中心”和内部执行任务队列相混。队列项目是 StudySession；执行任务队列是内部运行机制；知识库是持久产物视图。它们不共用一个待办状态，也不新增 Inbox 数据副本。

知识库的列表、详情、聚合浮层和未来图谱共用同一份数据。MVP 提供数量、来源、可证实的关系与状态管理；交互图谱不是本轮额外承诺。关系标明依据，不把共同来源或模型建议冒充已验证的语法关系。

组件独立于 shell；Study 的文档与对话可在窄屏切换，但保留同一会话与位置。正式界面约束见 DESIGN，mock 样例仅提供视觉方向。

## 4. 输入与保存

MVP 接受字幕（可挂载视频／音频）、纯文本、EPUB；PDF 转纯文本降级，暂不做独立渲染器。视频默认外部引用；所有素材可明确选择外部引用或管理副本，并知道大小和资源可用性的后果。

原始资源、规范化文本、sidecar 与用户状态分开保存。管理副本不改原文件，外部资源失效不删除已生成的规范文本。content_hash 表示规范化 logical text，原文件校验另用 source_sha256。

NFC、LF、code point 半开区间及版本来源的字段级要求只在 data-model §§0、8 定义。Sidecar 为 msgpack；SudachiDict 版本与释义词典版本不是同一命名空间。

## 5. 算法与 AI 分工

SudachiPy + SudachiDict A mode 承担分词与形态信息，用户导入的词典提供可追踪的释义。模型负责语境判断、串讲、文化与用户讨论。偏移、token 对齐、lexeme 与 anchor 派生由后端完成，不让模型猜数值。

AI 不进入整部材料预处理。翻译与依存结果暂按懒生成、缓存处理，按 data-model §8.3 的输入与资源版本隔离；依存分析以及分析结果可视化是否进入 MVP 尚未决定。视频转写、生肉处理和 STT pipeline 不在 MVP。

## 6. 解析文档与学习 Agent

### 6.1 文档与对话并存

初始生成提供完整可读的解析；Agent 可回应问题、缩写、扩写、纠错、删除和重组小节。文档是当前讲解结果，对话保留讨论过程。首版不再限于追加小节或一次追问。

工具写入经统一执行器校验与提交。每轮使用当前文档和必要学习上下文，不重复注入历史全文；上下文裁切保留必要决定与未解决问题。预算达到上限暂停并保留现场，不默认自动提取。详细工具与上下文规则见 prompt-contracts §3。

### 6.2 结束讨论与提取

用户“结束讨论并提取”固定当前完整文档版本。提取失败区分自动重试耗尽与用户手动重试：自动重试耗尽后保留同一 revision，并提供“暂时搁置”和“创建关联新会话”出口；手动重试仍只重试该 revision。当前不提供同一会话退回 discussion 或忽略失败强制成功。提取成功后用户可确认本次结果，默认确认后完成的会话退出队列但留在记录。

会话完成独立于知识点当前意愿与意愿变化。知识库随后改变 srs/reference 不让旧会话重新排队；复用已有 KP 时可确认沿用既有选择。具体阶段与原子边界只在 data-model §4 定义。

### 6.3 多选与自动模式

普通多选是一次创建多个可讨论的会话，首版每会话仍为一句，分别排队调用；不自动合并多句 prompt，也不自动跳过讨论。
（后续如得到反馈且判断确有需要，可额外增加多句合并解析的模式，这涉及到数据模型的重新论证）

显式选择“自动生成并提取”才创建 automatic 会话：生成后固定文档并提取，跳过讨论，仍由用户确认复习意愿。它不授予默认候选自动建卡的权限。并发与费用预算可配置；预取和滚动式全量处理暂不做。

## 7. 知识点与历史

Lexeme 是算法身份与学习证据底座；KnowledgePoint(i.e. KP) 是提取产生的形式级学习对象；Occurrence 保存每次出现及其具体讲解。查词、导入词表、Annotation 不自动创建 KP。

**归一锚点，不归一内容。**同一形式可以有多条不同语境的讲解；合并不改写旧 Occurrence 的原始指向。知识库展示的是这些实例及其来源，而非强行统一的权威定义。

历史保护按数据性质执行：被引用内容与学习事实可追溯，当前状态、用户意愿、笔记和批注允许修改。Agent 编辑不改变历史复习卡引用的讲解；规则见 data-model §0.1 与 ADR-039。

## 8. 复习与再遇

知识点存在不等于进入复习。用户明确选择 Occurrence “安排复习”才进入新卡配额流程；“仅作参考”保留知识与检索并暂停符合有效意愿的已有复习。改回 srs 恢复既有进度，不清零历史。排程字段以 data-model §7 为准。

复习内容以 Occurrence 为粒度；用户明确加入与 ReviewItem 的创建／复用原子提交，同一 KP 下不同 Occurrence 可以分别进入复习。ReviewItem 是复习调度绑定，不等同于最终渲染卡片；CardDefinition 可后补。KP `default_retention` 对用户称为“默认复习策略”，Occurrence 使用 `retention_override` 的 `inherit` / `srs` / `reference` 局部决定。局部值与用户是否确认分开：默认 inherit 不自动建卡，明确沿用也须确认具体 Occurrence，并记录 `effective_retention_at_confirmation` 与 `retention_override_at_confirmation` 快照。等待配额的是已有 queued ReviewItem，不存在正常的“已加入但待建卡”状态。卡片呈现该 Occurrence 的 anchor、例句、Span 与引用小节，有原声音频则带上；无音频正常使用，TTS 非必需。

修改 KP 默认复习策略只影响继承它的既有复习项，不为历史或未来 Occurrence 批量建卡。KP 合并／撤销只通过 canonical 归属聚合展示，不迁移 ReviewItem 或改写复习历史，也不自动覆盖局部决定或切换继承策略的来源；改变这些用户选择须另有明确操作。见 ADR-041 与 data-model §3。

已讲解次数来自 Occurrence，材料出现次数来自算法内容索引。首版“有已知证据支持的材料覆盖率”按有效用户断言／已发布导入支持的 token 比例计算，按不同 Lexeme 的覆盖另列；无来源时说明尚未建立估计，不把缺证据解释为不会。词形级证据不自动提升为整词认识。

合格词汇卡的 SRS 估计独立展示，须基于实际复习内容与同目标的累计历史，带求值时间；不生成永久 srs_matured KE，不默认并入证据覆盖。知识点进度仍来自 KP/SRS，各指标不相加、不互相校验；受控的共同来源不意味着统计口径相同。完整分母、来源与传播规则见 data-model §§2、10。

阅读、查词和播放不产生 KnownEvidence。LexemeActivity 与阅读曝光统计后置，首版只显示“材料中出现”，不声称“用户见过”；导航位置不充当阅读进度。词频稀疏索引与证据增量摘要是首版性能底座，按 data-model §11 执行，不依赖每次扫描历史或整部 sidecar。

语法模式自动匹配未进 MVP，因此不能承诺语法再遇率与词汇锚一致。推荐器、活用覆盖推荐和完整听力题型系统后置。Anki 导出保留用户显式选择、字段映射与外部发送确认，缺失媒体不阻止导出。

## 9. 候选确认与知识管理

确认界面按本次提取结果中的 KP 折叠，不按全库未确认 KP 代替会话进度。可逐项选择、稍后继续、沿用既有选择；最后完成本次结果确认后退出解析队列。没有有效候选时解释结果，让用户明确完成。

primary/secondary 只表达最终解析总结中的显著性、候选排序与 queued 复习项的首次准入优先级；模型不替用户决定是否复习。有效 srs 不代表已经确认加入；明确加入即有 ReviewItem，等待配额与已准入由其状态区分。

队列可以显示真实数量和阶段进度，不制作未读红点、逾期债务或清空压力。长期知识管理由知识库承担，不要求从未完成会话列表寻找历史知识。

## 10. 互操作

Yomitan ZIP 是用户词典的第一等交换格式，内部采用 canonical dictionary model；结果显示来源与版本，定义保留文本投影和可选富文本。其他词典格式由未来 importer adapter 接入。版权内容不随开源发行包分发。

查词使用点击或键盘选择，不占用 Yomitan 的 Option/Alt + hover。Anki/jpdb 已知词表导入落在 Lexeme 的 KnownEvidence，不自动创建知识点；保留原始词串与消解来源，按运行幂等发布并报告未消解项。用户可撤回错误来源、声明认识／不认识或清除人工覆盖；当前明确否认优先于外部导入与 SRS，旧断言不因清除覆盖而复活。Anki 导出、数据导入导出及本地 API/MCP 是互操作方向，具体阶段安排由后续任务同步。

## 11. C 类用户的发现机制

整体后置。若实现，用可配置的可疑句高亮与单条反馈，位置复用 Span；不直接触发全量解析。候选信号包括实体、语域变化、流行语和互文线索，效果需实证。

## 12. 共享

解析共享后端暂缓。保留模型、prompt、原句和用户评价等来源信息，为未来质量筛选留口；不建立默认跨用户共享池。

## 13. 成本与商业

开源、基础功能免费、默认 BYOK。打包 LLM/TTS 服务订阅仍是可能方向，尚不据此约束产品。实验 9 分别测生成、讨论工具循环、提取、条件身份消解的成本与延迟，再推算稠密使用成本。

预算控制属于执行机制，学习是否结束属于用户会话操作。可用模型能力差异通过工具适配或明确的只读降级呈现。

## 14. MVP 边界

**保留**：素材导入与阅读／播放；算法查词；Annotation；学习会话与队列；独立文档／对话工作区；Agent 文档编辑与有边界的笔记工具；两段式提取；会话结果确认；两层知识模型；知识库基础管理与聚合；SRS、暂停恢复、配额与复习视图；Anki 导出。开发阶段允许按 ADR-042 对明确指定的开发／测试数据集显式重建；首次真实数据或对外发布前必须建立受支持 schema 基线。

**条件式**：依存分析与可视化，按引入 GiNZA 的整体成本决定。

**后置**：LexemeActivity／阅读曝光统计、STT、PDF 原生布局、推荐卡片流、语法模式自动匹配、解析共享、完整听力题型、联网检索、UI 多语言、交互知识图谱。多句联合会话仅留有序原文关联结构，首版仍一句。

数据层必须先明确：历史引用、文档版本、提取尝试、会话完成与 KP 意愿分离、Span/code point、资源版本来源、KP 形式身份与可撤销合并、复习历史与当前状态分离。具体字段与不变量集中在 data-model，本文不再复制字段清单。证据按词增量汇总、材料词频稀疏索引、可恢复导入与版本一致的投影重建属于首版查询要求；性能实测决定批大小和最终聚合缓存，不决定是否允许交互查询全扫历史。

## 15. 未决事项

全项目唯一 open items 索引。编号不重排；已经解决的条目保留落点，避免旧引用变义。

1. **解析模块默认组合**：临时值见 prompt-contracts §1，待实验 5。
2. **依存结果是否持久化**：暂缓存，待实际使用的性能数据。
3. **后端分发方式**：本地服务／打包／托管；本地 provider 配置和秘密分离、keyring 优先及显式 0600 文件降级已定，托管需另作安全决策。
4. **模式语言覆盖与严格度**：category/form、Clause/V 边界、none 语义、决策表与版本迁移，待实验 2。
5. **盈利点**：暂不展开。
6. **算法能力扩展**：相关性、检索与难度推断的实际边界，另行探索。
7. **AI 提取之外的 KP 构造**：例如原文选区微型解析；不阻塞 MVP，不能通过 Annotation 自由文本直接提升绕过当前契约。
8. **GiNZA 是否进入 MVP**：仍未定。依存结果是否持久化随是否纳入 MVP 一并评估。
9. **B 类准入路线**：完整自建播放器与承接现有 asbplayer/Yomitan 工作流的取舍尚未定；当前规范不宣称已达到替代播放器的能力。
10. **BYOK onboarding**：无配置时浏览、算法、批注和证据仍可用，配置提示时机与恢复路径待设计。
11. **跨语言命名空间**：MVP 日语，未来 pattern_grammar_version 是否采用语言前缀。
12. **工具栏与查词细节**：分组、固定查词结果、多词典排序、外部链接、来源展开层级；既定的来源标签和键盘规则不重开。
13. **已解决：导航／关窗不自动结束讨论或提取**。显式结束操作与 automatic 创建模式见 §§6.2–6.3；上下文预算耗尽只暂停。旧 background 关闭触发不再保留为等待实现的类型。
14. **已解决：入口命名**。实体与记录层采用学习会话、学习记录、知识库；顶级导航采用主页、素材库、知识库、解析队列、学习中心。早期的宽泛队列标签已退役，见 §3 与 DESIGN。
15. **Agent 运行参数与兼容矩阵**：上下文／工具调用／费用预算默认值，支持编辑的 provider 能力验证，草稿撤销与协议日志保留参数，需实验与实现验证。
16. **综合已知估计的规则与校准**：是否将合格 SRS 信号并入综合词汇估计、阈值／时间范围、多卡聚合及来源权重的校准；首版采用 data-model §10 的显式证据集合覆盖，SRS 单列，不输出未经校准的综合掌握概率。资格约束与时间有效性已定，不能借规则未定放宽传播。
17. **已解决：用户已知判断可纠错**。采用正向 KE + 追加来源撤回 + known/unknown/clear 当前裁定；明确词形／Lexeme 作用域和跨来源优先级，见 data-model §2.2。unknown 不是负向 KE，clear 不恢复旧人工断言。
18. **已决定：活动统计后置**。首版无逐次曝光／查词／播放日志，不以导航位置推断阅读；未来先定义阅读范围、跳读与活动聚合生产者，入口见 data-model §2.5。算法材料词频索引仍属首版。
19. **汉字与表记能力**：orthography 是否作为独立解析模块；词典汉字条目的导入／展示范围；未来认字与同表层 lexical KP 是否共享身份、用户意愿和 SRS。tags 不参与身份，不能在此决定前承诺 lexical + kanji 标签没有迁移风险；本轮不新增模块、shape 或汉字卡。
20. **提取与确认的恢复能力**：带用户 hint 的重抽、成功结果的显式弃用／候选排除、queued 首次准入优先级覆盖，以及同一会话返回 discussion 仍未决定。当前失败区分自动重试耗尽与手动重试；耗尽后可搁置或创建关联新会话，手动重试保持同一 revision；不把 reference 当“排除此候选”，也不提供同会话退回 discussion 或忽略失败强制成功。
21. **查询性能预算与最终结果缓存**：实验 11 确定参考硬件／规模、响应预算、批次与后台时间预算、可取消重试及 checkpoint 参数、动态结果缓存有效期／可接受陈旧时间、材料与全库聚合的物化范围。按词摘要、稀疏反向索引、持久失效、短事务与原子代次切换已定；测量未完成不宣称达标。
22. **外部已知词表输入与默认筛选**：首个 Anki/jpdb 适配器接受的导出字段／格式、成熟度筛选和权重配置。首版只接受用户明确选择的“已知词表”，不能把普通牌组全量词条或未核验导入自动视为认识。不同快照目前追加留痕、缺项不表示否认；自动替换来源快照后置，若要引入须另定语义。

23. **主页默认内容与排序**：主页保留为顶级导航入口，但其默认聚合内容、排序、空状态和进入活动会话／学习中心的优先级尚未决定。在决定前仅显示非误导的“主页内容待定义”占位，不把返回位置、队列数量或推断的学习状态冒充为默认首页。

24. **阅读器基座支持范围与内容定位对齐**：已决定近期 reader-first 纵向交付，AI/音视频暂缓；以现有 EPUB 研究为输入，优先细化受控正文与语言投影分离的路线。具体资源/规范投影/版本契约、正文映射及精确选区输入仍需对应切片的局部契约对齐；研究报告不是字段批准。首轮先验证连续阅读，分页是否进入首版、正式竖排/EPUB2 覆盖、代表书与复杂 ruby/字体/脚注、词典富文本和日常备份/导出最低要求随实际切片收敛。现行 data-model §8 在明确修订前继续约束实现；不得把“EPUB 文本锚点已定”解释为禁止获授权的新阅读内容模型决策。近期范围与停止点见 [阅读器范围](reader-foundation/scope-draft.md)，当前任务见 [派发入口](reader-foundation/README.md)。原始资源保留与数据保护规则继续有效。
