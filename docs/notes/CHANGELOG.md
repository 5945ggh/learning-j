### 实质修正一：撤销 `study_status`，`retention` 承担唯一的学习意愿

曾计划另设一个「是否加入学习」的状态字段。摊开四种组合后发现，除「学 + srs」外的三种行为完全一致——因为 Occurrence 无条件记录、KP 层无条件建立，**KP 的存在从来就不是一个可选项**，用户唯一真正的决策就是「排不排程复习」。

因此 `retention` 语义改为**用户的决定**，抽取段输出的降级为 `suggested_retention`。用户在 triage 页选「不学」即写入 `reference`。

连带修正：记忆注入**不再按学习意愿过滤**（原 `prompt-contracts.md` §4.1 第 4 步）。该过滤在新旧语义下都是错的——记忆注入回答的是「讲过没有」这一确定性事实，而用户判为 `reference` 的文化互文正是最需要被注入的。

### 实质修正二：抽取由用户主动触发

ADR-017 的会话形态使抽取失去了自然触发点。旧流程「生成 → 自动抽取 → 用户读完时抽取已完成」的不阻塞性，依赖的是「解析是一次性讲稿」这个已被撤销的前提。

新流程：`生成 → 追问 N 轮 → 用户点「提取知识点」→ 抽取 → triage`。该动作即会话终点，`session_closed = true` 后不再接受追问。

两条例外路径（批量、关窗后台补跑）无 triage，走 `salience` 默认值——这是 `salience` 在有了 triage 页之后仍然必要的唯一理由。

新增字段：`Analysis.session_closed`、`Analysis.extraction_trigger`。

### 实质修正三：Span 定位改为原文子串

模型原本输出 `char_start / char_end`。改为输出 `surfaces`（原文子串数组），后端 `find_all` 定位。

理由不是准确率，是**失败模式的可检测性**：偏移的典型失败是「整体偏了两位」，偏移后 span 仍落在句内、仍能与某个 token 对齐，`alignment_status` 仍是 `aligned`，是静默错误；子串的失败是「找不到」，100% 可由代码判定。

不加消歧字段。多处命中时为每处各产生一个 Span，全部标新增的 `ambiguous` 状态。理由：Span 的三个下游的歧义代价都是视觉性的，不污染身份、不产生不可逆数据。

ADR-009 第 3 条据此收紧为一般规则：**抽取段的输出中，任何可由算法从原文推导的内容一律不由模型给出。**

### 实质修正四：`lexeme_id` 不再包含 `dict_version`

原派生式为 `normalized_form + pos + reading_form + dict_version`。这是对 ADR-018「所有 Lexeme 记录必须**带**词典版本号」的过度推导——带字段与编进 id 是两件事。

编进 id 的代价：词典升级使全库 `lexeme_id` 变更，历史证据全部指向旧 id，词频与覆盖率查询永远要过映射层；而那张映射表实际只能靠「三元组相同即同一词」重建，等于自造一道必须再拆掉的墙。

改为三元组派生，`dict_version` 作为普通字段记在 sidecar 与 KnownEvidence 上。映射表规模从全库降到实际漂移的那几百条。

## v4

核心改动两条：

1. **引入 Lexeme 层与 KnowledgePoint 层的分离**（原 ADR-026，现 ADR-005 决策一）。撤销 v3 把三元组代理主键与语法点自签发 ID 合并为同一 ID 空间的建模错误。该错误的荒谬推论是：阅读推断产生的已知状态证据指向三元组主键，而后者是 KnowledgePoint，于是用户读过的每个词都会创建一条知识点，一部小说一万条量级。
2. **撤销标题层级契约，解析改为可交互文档**（原 ADR-028，现 ADR-017 决策二、三）。

### v4 新增

- `retention` 字段（`srs` / `reference`），一个枚举解决 C 类「要批注与检索、不要复习」；
- `salience` 两级候选，修订 v3 的「默认全部加入」；
- Span 升格为四方共用的值对象；
- AnalysisSection 可寻址，Occurrence 引用 `section_id + revision`；
- Sentence 的 `anchor_type` + `anchor_payload` 两段式形状；
- 记忆分作品笔记与学情画像，槽位上限由后端强制（ADR-029）；
- Annotation 明确为叶子实体（ADR-030）；
- 素材的统一抽象：素材 = 有序 Sentence 序列 + 可选时间戳 + 可选 locator；
- 解析输出语言与 UI i18n 分离（ADR-024）。

### v4 撤销标题层级契约的实证依据

`网页对话版本的例句解析实例.md`：前沿模型在高 thinking effort、单次长输出内部，会把并列小节写成 `#` 与 `##` 混用。这类失败率不低、无法可靠检测，而 v3 把整条抽取链路押在了它上面。

同一份实录还提供了另外三项依据：

- 信息密度最高的一段（`よっと` / 词边界误判）源于用户主动追问 → 解析必须可追问；
- 一次面向低水平学习者的解析里出现了《こころ》互文 → 好的解析本来就跨模块，硬档位是错误方向；
- 模型自发以「本句最值得带走的东西」小节收尾 → 该要求不需要诱导；
- 模型自发承诺并兑现跨句记忆 → 记忆注入有据可依；
- 模型自发判断字幕译文存在意译与未对齐 → 译文应标注为参考而非标准；
- 单句可抽出十条以上候选 → 「默认全部加入」不可行。
